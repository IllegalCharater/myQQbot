# myQQbot

基于 Electron、Node.js、OneBot v11 与 OpenAI 兼容接口的本地 QQ AI 机器人。
后端是严格 TypeScript（运行 `dist/`），前端是不打包的原生 ES Module，全部运行数据落在本地 `data/`。

>
> 本项目仅用于个人学习、技术研究与交流，不用于商业运营，也不鼓励将其用于批量营销、骚扰、垃圾信息、绕过平台限制或其他违规行为。使用者应自行遵守 QQ 平台规则、所接入模型服务的使用条款以及所在地法律法规。因使用、修改或分发本项目造成的账号限制、数据损失、费用支出或其他后果，由使用者自行承担。

本项目在既有开源项目基础上学习修改而来，请优先了解并尊重原项目作者及其许可：

- 原始项目：[Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)
- 此前的 QQ Agent 项目：[Kondius/qq-agent](https://github.com/Kondius/qq-agent)

本仓库中的修改不代表上述项目作者的立场。涉及第三方组件时，以其各自的许可证和使用条款为准。

主要能力：群聊/私聊的艾特、关键词、概率与全量响应，多轮工具调用，图片理解，表情包，网页搜索，
视频 URL 转写，图像生成（含图生图），以及可选的图片溯源、每日热搜播报；控制台提供模型、会话、记忆、
消息策略与用量的管理界面。

## 环境要求

- Windows（Linux 下可用 headless 的 `npm run server`）
- Node.js 20 或更高版本
- 一个兼容 OneBot v11 正向 WebSocket 的 QQ 协议端
- 一个 OpenAI 兼容模型 API
- 可选：视频转写需要 FFmpeg 并开通腾讯云录音文件识别极速版；图片溯源需要 Python（见下方「Python 工具」）；
  图像生成需要阿里云百炼的 API Key（按张计费，默认关闭）

SnowLuma 可作为协议端使用，但它是独立第三方项目，不包含在本仓库中，并受其自身 EULA 和使用条款约束。

## 安装与启动

按锁文件安装依赖并首次编译（源码在 `src/`，运行时跑的是 `tsc` 的编译产物 `dist/`）：

```bash
npm ci
npm run build
```

启动桌面端：

```bash
npm start
```

也可以双击项目根目录的 `启动QQ机器人.bat`（它直接起 `node_modules` 里的 Electron，跑的就是 `dist/`——
所以**首次双击前要先 `npm ci && npm run build`**，或者用 `npm start` 让它自己编译）。

仅启动 Web 服务（不开桌面窗口）：

```bash
npm run server
```

`npm start` / `npm run server` 会自动先编译一次（npm 的 `pre*` 钩子），所以日常不必手动 build。
随后访问 `http://127.0.0.1:3210` 打开控制台。

## 首次配置

启动后打开控制台，按顺序完成下面四件事：

1. **模型 API**：填 Base URL 与 API Key，点「获取列表」拉取模型并选择要用的那个。可以配多个提供商，
   每个模型有独立的输入/输出价格，供成本核算使用。
2. **OneBot 连接**：填协议端的 WebSocket 地址（以及需要的 Access Token）。地址变更保存后会立即重连；
   用 SnowLuma 时可以在同一页启动它、查看日志与 WebUI 地址。
3. **聊天白名单**：选择允许机器人工作的群聊或好友。白名单为空时可用「允许全部」临时放开，
   建议先只放一个测试群。
4. **响应与上下文**：在聊天设置里调整响应档位、关键词、人设与上下文参数。

### 聊天与上下文参数

聊天设置里有几个容易混淆的项：

- **动态上下文窗口**只限制一次放入【本次唤醒】的新消息条数，`0` 表示不限。
- **历史消息深度**独立控制窗口之前读取多少条记录，不受艾特、关键词、随机或响应档位影响。
- 当前窗口最早一条消息是历史边界：窗口内容只进【本次唤醒】，独立历史只从边界之前读取。
- **响应档位**只保存滑条位置，档位编号与随机概率由程序运行时计算，避免多份配置互相冲突。
- 所有发送统一使用**每分钟最多发送**这一项；回复态触顶时可按设置短暂等待，不再另设一套回复态频率。
- **单次提示词统一字符预算**控制完整 user prompt，`0` 表示不限（默认 32000 字）。超限时依次收缩
  表情目录、摘要、记忆与已读历史，本轮新消息不会被静默截断。
- **历史摘要字数**是摘要通道自己的候选上限，最终仍受统一字符预算约束。

请从低频响应开始测试，确认行为符合预期后再逐步放开。

## 可选功能

### 网页搜索与收藏夹

联网搜索**默认开启**，模型可以调用 `web_search`（搜索）与 `web_fetch`（读正文，≤2 万字符）。
搜索后端在设置页「搜索服务」里选：默认是免 Key 的 **Bing 网页解析**，也可以换成 DeepSeek 原生搜索、
智谱、博查、百度千帆、秘塔、Yandex 网页解析，或自行添加兼容 JSON / Bing 结果格式的自定义服务。

**Yandex** 这一路抓的是公开结果页（不需要 Key），但它有两个你应当知道的特性：**会被 CAPTCHA 拦**
（被拦时工具会明确说"要求人机验证"，而不是假装没搜到），以及 **Yandex 会改页面结构**。所以它的四个
选择器（结果容器类名、标题锚点类名、链接类名、摘要类名）都做成了设置页可改的字段：工具报"没有解析到
结果"时，把类名改成当前页面上的值即可恢复，不必等一次发版。搜索页地址也能换成 `yandex.ru` 等镜像。

**网页收藏夹**（同一页）用来告诉机器人「哪些站点是常看的」。**前三条都要填**：

| 字段 | 说明 |
|---|---|
| 枚举值 | 模型在 `web_search` 的 `site` 参数里传的就是它。只能是字母/数字/`-`/`_`（如 `wiki`、`news-yc`），**中文会被丢弃** |
| 网页地址 | 站点的域名（填整条网址也行，路径会被丢掉） |
| 用途 | **会随每轮提示词交给模型**，是它判断「该选哪一条」的依据 |
| 站内搜索地址（可选） | 见下。**想让"只在这个站里搜"真生效就必须填** |
| 结果容器类名（可选） | 该站结果块的类名；留空用通用解析 |

### ⚠️ 为什么「站内搜索地址」是必需的

实测 **Bing 对程序化请求完全忽略 `site:` 限定符**：带与不带的结果**逐字节相同**，换个必然被
收录的站点（如 zhihu.com）同样零命中；`cn.bing.com` 与 `www.bing.com`、中英文语言都试过，
行为一致。所以只填域名时，「限定在这个站里搜」**实际上没有生效**——收藏夹只影响排序与标记。

填了**站内搜索地址**才会真正去那个站自己的搜索页取内容（绕开搜索引擎）：

```text
https://zh.wikipedia.org/w/index.php?search={q}
https://your-docs.example.com/search?q={q}
```

`{q}` 是查询词占位符，**必须包含**，否则这一栏会被忽略（缺了它请求会打到搜索页首页、
返回"文不对题"的结果，比直接报错更难查）。留空则退回 `site:` 行为——对自建 SearXNG 等
仍认这个语法的服务有效。

**不知道填什么？点那一行右边的「检测」按钮。** 它会自动试常见的搜索入口
（`?q=`/`?query=`/`?search=`/`?keyword=`/`?wd=`/`?word=` × `/search` 与根路径），把可用的那个填进去。
`?word=` 是国内站常见的叫法（百度系）。判定方式不是"有没有抓到结果"，而是**减掉该站首页本来就有的
链接后还剩几条**——因为真实搜索页里满是导航链接，不减基线的话任何页面都"看起来有结果"
（实测 Bing 的结果页对正常查询和乱串查询都解析出 16 条，全是导航）。

检测**不保证成功**，三种情况会被拒并说明原因：
- 站点用 JavaScript 动态渲染结果（抓到的 HTML 里没有结果）——**百度百科就是这一类**（实测它的
  搜索页只返回 1.5KB 的空壳，正常页面是几十 KB，结果全靠 JS 渲染）；
- 查询参数名不在这几个里，或结果在另一个主机上；
- 站点需要登录或被反爬拦截（反爬时连结果标记都会被去掉）。

检测不出来时，**最可靠的办法还是自己搜一次、把地址栏的 URL 抄进来**：在站内搜一个词，看地址栏
`?` 后面的部分，把查询词替成 `{q}` 即可。**注意不要**用文章路径（`/wiki/{q}` 是错的，
`/w/index.php?search={q}` 才对）。浏览器 `Ctrl+U` 看**源代码**（不是 F12 的 Elements）里搜不到
你要的词，就说明这个站是 JS 渲染、这条功能对它无效。

**结果容器类名**留空时用通用解析（会带上一些导航链接）；知道该站结果块的类名时填上更准
（如 GitHub 是 `search-title`、MediaWiki 是 `mw-search-result`）。工具报「站内搜索没有解析出结果」
就是在说这个站的页面结构变了，改这一栏即可。检测按钮在通用解析能判定时不会覆盖你手填的类名。

> ⚠️ 站内搜索**不能突破网络封锁**：如果那台机器访问不了某个站（例如境内访问 Wikipedia），
> 站内搜索同样连不上。工具会如实报出超时/连接错误，而不是假装"这个站没有内容"。

这份名单会随每轮提示词交给模型，于是模型每次搜索都可以自己决定「只在这个站点里搜」，传的那个值就是
**枚举值**（不是域名——服务端自己查表得出域名与站内搜索地址）。这是照「反向搜图」那套做的：
**该不该限定、限定在哪，是模型的判断**，代码只负责路由与校验。填错枚举值时会被明确拒绝，
并把可选值连同用途回给模型让它改对，而不是静默搜出一个空结果。

「收藏夹的默认行为」那个下拉只管模型**没有**指定站点时走哪条路：

- **优先在收藏夹里查，再补全网**（默认）——按关键词先问收藏夹，命中排在最前；
- **直接全网**——只有模型显式指定站点时才查收藏夹。

两种情况下，指定的站点里没有对应内容时都会自动补上全网结果，所以**收藏夹不会让搜索变窄到搜不到**。
模型显式指定站点时这个下拉不起作用。名单为空时一次额外的请求都不会发，行为与没有这个功能时完全一致。

> 从旧版本升级：原先的「每行一个域名」名单会**自动迁移**成三元组（域名 slug 化成枚举值，如
> `news.ycombinator.com` → `news-ycombinator-com`），**用途留空**。请在设置页把用途补上——没有用途时
> 模型拿到的只是一串生造的枚举值，它无法判断该用哪一条。

结果里带 `fromBookmark` 标记的条目来自收藏夹站点，标记的含义只是「这个站点被收藏」，
**不代表它更权威**——system prompt 里对模型说明了这一点，涉及事实仍要交叉验证。

同一页还有两个**联网调用闸门**：单会话每小时上限（默认 20）与全部会话每天上限（默认 200）。
`web_search` 与 `web_fetch` 是**同一份额度**（两者都算一次外部请求）。默认的 Bing 解析不直接产生费用，
所以这里的默认值比搜图/转写宽松，作用是压住刷屏；若换到按次计费的搜索服务，请自行调小。

### 图片来源识别

设置页的「图片来源识别」**默认关闭**。开启后模型可以调用 `reverse_image_source` 工具：

- **trace.moe**（动画截图 → 番名 / 集数 / 时间点）不需要 Key。
- **SauceNAO**（插画与漫画 → 画师 / 作品 / 来源站点）**需要 API Key**，只能在设置页填写（输入框只允许
  写入或替换，服务端不会把原值返回浏览器）。未配置时这一路被跳过。
- **百度识图**（一般向兜底）不需要 Key，可以在设置页单独关掉。

模型每次调用还会给出「这是哪类图」（`anime` / `manga` / `illustration` / `unknown`），查询按类型走：
**先问这个类型的专属引擎，没结果或超时了再用百度识图兜一次；判不出类型时直接走百度识图**。
是否该查由模型结合上下文判断，代码不做关键词拦截；原图不会交给大模型。

三个引擎各有自己的请求超时与结果条数。**「总任务超时」（默认 35000 毫秒）是整轮上限、也包含图片下载**，
别把各引擎的超时之和顶到这个数上——留给每个引擎的时间是从这条总线上按顺序分的。

两个第三方接口都有配额（SauceNAO 免费额度尤其紧），因此有**每群每小时上限**（默认 5）与
**全局每日上限**（默认 30）两个调用闸门，超限时工具直接失败并说明原因。

识别失败时工具会说明具体原因（图片下载失败 / 图片下载超时 / 查询超时 / 第三方接口没有返回结果 /
队列已满），同一句话也写进日志（`[image-source] …`）。其中「图片下载超时」与「查询超时」是两件事：
前者是那张图取不下来，后者才是接口慢。反复出现查询超时就调大「总任务超时」。

搜索由常驻的 Python worker 执行，开启前请先按下方「Python 工具」把依赖装到配置的解释器里。
设置页的「测试连接」可以分别探测三个引擎，用来确认配置与依赖是否就绪。

### 每日全网热搜播报

设置页的「每日热搜播报」可配置启用状态、北京时间、目标白名单群、每次条数、平台范围与是否附链接。
数据来自极数本源的[全平台热搜聚合接口](https://apizero.cn/marketplace/hot-search/sub/all)；
默认关闭，每天 09:00（`Asia/Shanghai`）、10 条且不附外链。目标群只会从当前 OneBot 群列表与发送
白名单的交集中选择，实际发送仍走统一的限频与长度保护。

API Key 可在设置页填写，也可沿用 systemd 环境注入：

```ini
Environment="HOT_SEARCH_API_KEY=<sk_live_xxx>"
```

未配置 Key 时仍会按接口文档尝试匿名调用，但匿名额度和 QPS 较低。Key 只通过
`Authorization: Bearer <API Key>` 请求头发送，不进入 URL、日志或控制台响应。任务元数据保存在
`data/hot-search-state.json`，只记录日期、状态、条数、目标群和脱敏错误摘要；服务重启后据此避免
同一天重复播报。错过当天计划时刻不会补发，可在设置页查看原因或手动播报。

除定时播报外，模型还有一个只读工具 `get_hot_search`：群友问「今天有什么热搜」时它会自己去取榜单，
**要不要发、发几条由模型自己决定**。因此启用开关但不选目标群，就是「只让模型按需查、不每天播报」的组合
——定时任务在目标群为空时不会排定。

### 视频 URL 转写

群聊或私聊发送 `/转写 <视频URL>` 后，机器人回执任务号，再由单并发后台队列完成 FFmpeg 音频提取与
腾讯云录音文件识别极速版请求。该命令只接受公网 `http://` / `https://` 地址；本机、内网、链路本地、
云元数据地址以及重定向到这些地址的请求都会被拒绝。

B 站普通公开视频可直接传 `bilibili.com/video/...` 或 `b23.tv/...` 链接，也可以回复一张 B 站视频卡片
并发送 `/转写`。解析层会在任务真正执行时取首个分 P 的短时效音频地址，再交给同一套安全代理和 FFmpeg；
单独转发卡片不会自动产生转写费用。第一版不携带 B 站登录 Cookie，因此番剧、课程、地区/登录受限内容
不在支持范围内。

实现上把临时 MP3 作为二进制请求体直接上传到极速版独立 HTTPS 接口，不经过 COS、不创建公开音频 URL；
完整视频不会先下载落盘，临时 MP3 与长结果文本在任务结束后删除。单音频按官方限制最多 2 小时且不超过
100 MiB，配置中的时长和大小只能进一步收紧。

除了 `/转写` 命令，模型也可以自主调用 `transcribe_video` 工具。`/转写` 是确定性快路径：立即回执，
完成后由后台队列**直接**把识别文本发到原会话，全程不经模型、零 LLM 成本。工具路径则由模型在这一次
运行里自己决定说不说话，识别结果作为一条【转写结果】异步进入会话上下文，到达时再跑一次模型来转述。
**识别失败也走同一条路**（回流一条【转写失败】条目，由模型如实交代一句），队列不再代它往群里贴报错。
因为转写按次计费，这条模型自主路径受**每群每小时上限**（默认 3）与**全局每日上限**（默认 10）约束，
`/转写` 命令也受这两项限制（2026-10-10 起闸门在队列里，两条入口共用同一本账）。

凭证可在设置页填写，生产环境建议用 systemd 环境变量注入：

```ini
Environment="QQ_AGENT_TRANSCRIPTION_ENABLED=true"
Environment="TENCENTCLOUD_APP_ID=<your-app-id>"
Environment="TENCENTCLOUD_SECRET_ID=<your-secret-id>"
Environment="TENCENTCLOUD_SECRET_KEY=<your-secret-key>"
Environment="FFMPEG_PATH=/usr/bin/ffmpeg"
```

FFmpeg 路径也可以由设置页的 `transcription.ffmpegPath` 指定。SecretId/SecretKey 输入框只允许写入或
替换，服务端不会把原值返回浏览器。日志只记录任务 ID、状态、音频大小、耗时和错误码，不记录原始 URL、
请求签名、识别文本或凭证。

### 图像生成

群聊或私聊发送 `/画 <画面描述>`，或让模型在合适的时候自主调用 `generate_image` 工具（"给我画一只戴
墨镜的鲸鱼"）。**回复一张图片 + `/画 <描述>`** 就是图生图：以那张图为参考图改写它（"把这张图改成赛博
朋克风"）。出图要几十秒，所以两条路径都是"先入队、再由后台单并发队列画好并把图直接发进群"。

底层用阿里云百炼的千问图像生成与编辑模型（同步接口），默认 `qwen-image-2.1-turbo`，可在设置页换成
`qwen-image-2.1-pro` / `qwen-image-3.0` / `qwen-image-3.0-pro`（只有 3.0 系列支持负向提示词）。
接口地址、模型与 API Key **必须同一地域**；地址可以用默认的 `https://dashscope.aliyuncs.com`，也可以填
业务空间专属域名（`https://{业务空间ID}.cn-beijing.maas.aliyuncs.com`），或把整条接口地址粘进去。

提示词分两层：**模型负责把群友的话写成一段真正的出图描述**（主体、场景、画风、构图、光线），
设置页的**风格提示词**（默认一句中性的质量描述，留空即不注入）再由后端拼在后面，管"怎么画"。这一层对
模型不可见，改一处全局生效。

因为出图**按张计费**，两条入口共用同一套上限（默认每群每小时 3 张、全部会话每天 20 张），
`/画` 命令同样受限（转写 2026-10-10 起也在队列里设闸门，两条入口共用同一本账）。**两条入口的收尾也一样**：图片发出去之后都会让模型再跑一轮，
让它顺口补一句（也可以什么都不说）；画失败或没能发出去时，同样由模型如实交代，而不是机器人贴一句
机器味的报错。代价是每条 `/画` 多一次 LLM 调用。

API Key 可以填在设置页，也可以用环境变量注入：

```ini
Environment="DASHSCOPE_API_KEY=<your-api-key>"
```

日志只记录任务 ID、状态、图片大小、耗时和错误码，不记录 API Key、画面描述或图片地址。

### 扩展能力

扩展是"额外且相对独立的功能"，可以提供**模型工具**、**斜杠命令**，也可以往系统提示词里加/改内容。

**开关与装载是两件事**：

- 设置页的「扩展能力」那一栏管**能不能用**（每个扩展一个开关）。
- **真正装载/卸载在群里敲 `/能力`**：

  ```
  /能力                看列表（哪些已加载、哪些还没）
  /能力 加载 <扩展 id>   装载
  /能力 卸载 <扩展 id>   卸载
  ```

  （`/扩展` 是 `/能力` 的别名，用法完全一样；扩展自己也可以给自己的命令声明别名，比如参考扩展的
  `/时间` 也能敲 `/time`。）

**模型碰不到装载这件事**：未装载的扩展，它的工具根本不在模型的工具表里 —— 它连"有这个能力"都看不到。
什么时候把这个能力打开，由人决定。

装载后空闲超过「空闲卸载（秒）」会自动卸载，并调用扩展自己的 `dispose()` 放掉它占用的资源（子进程、连接、
大缓存），之后再用会重新加载。**注意卸载释放的是扩展自己持有的东西，不是代码本身**：Node 没有模块卸载，
模块代码会一直留在内存里 —— 所以没有 `dispose()` 的扩展，卸载后等于什么都没发生。填 `0` 表示常驻不卸载。

**接管模式**：个别扩展声明为 `override`，装载它会让**那个会话**的模型侧整体让位 —— 工具表、
斜杠命令、系统提示词都换成它的（安全规则与工具调用协议两段强制保留）。

**接管是按会话算的**：在哪个群敲 `/能力 加载`，就只有那个群被接管，别的群照常。所以"A 群换一副
脑子、B 群照常"是可以的。同一个群同时只能有一个接管者。

想让它**开机就接管某些会话**，写进 `data/config.json`（改完重启）：

```json
{ "extras": { "override": { "group:123456": "扩展id", "private:789": "扩展id" } } }
```

键是 `group:<群号>` 或 `private:<QQ号>`。群里敲 `/能力 加载` 建的那一份只在本次运行有效，
重启后回到这份配置。

> ⚠️ **开关的改动需要重启才生效**（工具表是每次请求前缀的一部分，运行期增删会打散模型侧的提示词缓存）。
> 「空闲卸载（秒）」与「每小时装载上限」改完保存即时生效 —— 前者同时也是**接管的生命时间**：
> 到点后附加的扩展被卸载、被接管的会话交还主流程（填 `0` 表示不自动交还）。

每个扩展也可以在 `data/config.json` 里单独覆盖要不要启用：

```json
{ "extras": { "enabled": { "clock": false }, "idleUnloadMs": 600000, "maxLoadsPerHour": 20 } }
```

`enabled` 里没写的扩展按它自己的出厂默认值走。**白名单群里的任何人都能敲 `/能力`**（它受「每小时装载
上限」约束）—— 不想让群友用，就在设置页把对应扩展关掉。开发说明见 `docs/extras-design.md`。

### 跑团（TRPG）

让机器人在**某一个群**里当跑团主持人（DM）：它负责叙事、扮演所有 NPC、裁定玩家行动的结果；
而 HP / SAN / 属性技能 / 场景 / 剧情旗标这些**状态由程序掌管**，AI 只能通过工具去改 ——
所以它没法在故事里随口把你"说死"。

**怎么开一局**（三步）：

1. 设置页「扩展能力」那一栏打开**跑团（TRPG）**，然后**重启**（这一栏的开关都是重启才生效）。
2. 在那个群敲：

   ```
   /能力 加载 trpg
   ```

   `trpg` 是**接管模式**的扩展，所以只会接管你敲命令的那个群，别的群照常聊天。
   想让某个群开机就进跑团，写进 `data/config.json`：

   ```json
   { "extras": { "override": { "group:123456": "trpg" } } }
   ```

3. 跟群友说一声"要跑团了"，DM 就会开局、建人物卡、带你们玩。**开局时可以让它用某份剧本**（见下）。

**群里能敲的命令**（零成本、不消耗模型调用）。**按开一局的顺序**排，一条命令一件事：

| 命令 | 作用 |
| --- | --- |
| `/跑团`（别名 `/trpg`） | 看当前局势。已经开局 → 看**你们已经知道**的（标题、场景、见过的人与他们的 HP/SAN 与属性、公开的剧情旗标、最近几次掷骰）；还没开局 → 给一份**向导**（按「定模式 → 传剧本 → 开局」说下一步） |
| `/模式 [助手\|DM]` | 第 1 步：看 / 切换这个群的模式（见下）。不带参数就是看当前的 |
| `/剧本 [名字]` | 第 2 步（**可选**）：把一份剧本收进剧本库 —— **先把剧本作为文件发到群里，再引用（回复）那条消息**敲这一条。**不带名字就用文件名当名字**；没引用文件就是**列出剧本库** |
| `/开局 [剧本名] [规则表 id]` | 第 3 步：开一局。**不带名字就是列出有哪些剧本可选**；带了名字但库里没有 → 照常开局，只是**没有注入剧本**（剧本是可选的） |
| `/掷骰 3d6`（别名 `/roll`） | 自己掷一次。支持 `3d6`、`d20`、`1d100`、`2d6+3`、`2d6+1d4`（多组相加）、`4d6kh3`/`4d6kl3`（留高/留低）、`(2d6+3)*2`（括号与四则）、`1d100b2`（奖励骰） |

> 这五条**各是一条命令**，没有子命令 —— `/跑团 开局 灯塔` 那样敲不会被当成开局，
> 它会回你一张命令清单。（早先的子命令写法已经作废。）

DM 那边还有一张**只有它看得见**的完整局势（包括还没登场的人、还没说破的暗线）——
它不会把这些念出来，你在故事里慢慢发现。

**每个群可以选两种模式**（`/模式 助手` / `/模式 DM`，**下一轮发言生效**）：

| 模式 | 它是谁 | 能做什么 |
| --- | --- | --- |
| **DM 模式**（默认） | 跑团主持人 | 叙事、扮演 NPC、建人物卡、改 HP/SAN、记剧情旗标、掷骰检定、还能开局与存剧本 |
| **助手模式** | 只掷骰 | **只掷骰**：群里发一个骰子表达式（`3d6`、`d20`、`4d6kh3`…）它当场掷、当场回话；**别的消息它一个字都不回，也不惊动模型** |

助手模式**只暴露掷骰与发言两个工具**（不是"靠提示词请它别动别的" —— 那些工具压根不在它手里），
**连人格都不注入**。更彻底的是：**那个群里一次模型调用都不会发生** ——
认得出骰子就掷，认不出的（闲聊、@ 它、`3d6 帮我看看` 这种半句话）**静默拦下**，不花钱、也不刷屏。
所以同一个机器人可以**既在一个群跑团、又在另一个群当骰子机器人**：
模式是**按群**记的，存在 `data/trpg/modes.json` 里。

**DM 模式下上下文会自动放宽**：跑团一局里的人物卡、旗标、剧本正文与聊天记录每轮都要带上，
默认那点窗口会让 DM 想不起十分钟前说过什么。所以只要某个群在 DM 模式，
它的**新消息窗口、历史深度与提示词预算**都会**至少**抬到 200 / 200 / 60000
（**只抬不降** —— 你自己在设置页配得比这宽就照你的；配成"不限"就还是不限）。
这**只影响那个群**，别的群一个字都不变。助手模式不抬（它根本不跑模型）。

切模式**不会删掉正在跑的那一局**：切回 DM 就接着跑，存档一直在。

### 跑团的剧本与规则表

两者都是**数据文件**，住在数据目录里。设置页「跑团」那一栏能看能删 —— **面板上不能编辑、也不能上传**
（上传走群里那条命令）。改完**不必重启**。

**加一份剧本有两条路**：把文件直接放进 `data/trpg/scenarios/`，或者在群里**把剧本作为文件发出来、引用它敲
`/剧本`**（支持 `.md` / `.txt` / `.docx` / `.pdf`）。

文件**本来就是下面这个格式**的话直接用，一次模型调用都不花；只是普通设定、模组、或者扫描出来的资料
（也就是**不是**这个格式），机器人会**让模型把它整理成这个格式**再存 —— 会多等一会儿、也多花一次调用，
回执里会写明"已让模型整理过"。整理只做提取，不会替你编剧情；原文里没提到的旗标与人物不会凭空出现。

**剧本**放在 `data/trpg/scenarios/<名字>.md`。格式是「几行骨架 + 一段正文」：

```markdown
---
title: 废弃灯塔
rule: coc7
scene: 午夜，码头
flags: {"灯塔已熄":"是","真凶是守塔人":{"value":"是","visible":false}}
characters: [{"name":"守塔人","visible":false,"hpMax":12,"stats":{"侦查":70}}]
---
这座灯塔三年前就废弃了。
守塔人其实是……
```

`---` 之间的几行是**骨架**（可省略任意一行，也可以整段不写、只留正文）：开局时
`title` / `scene` / `flags` / `characters` 会**直接落进那一局的状态**（人物卡与旗标都支持隐藏 ——
`visible: false` 是"玩家还没见过/这是暗线"）。`---` 之后是**正文**（最多 4000 字），
它会进 DM 的上下文，但它**是给 DM 看的设定、不是玩家已经知道的事**。

**检定规则表**放在 `data/trpg/rules/<id>.json`，内置的 `generic`（掷高为佳）与 `coc7`（COC 7 版六级）
会在第一次用到时自动写进去。要加自己的，照抄一份改 `levels` 就行 —— 每一级是一个
「条件表达式」，七个变量：`total`（合计）`target`（目标值）`count`（颗数）`faces`（面数）
`roll`（单颗时的骰面）`max` / `min`：

```json
{
  "name": "我的房规",
  "requires": { "condition": "count == 1 and faces == 100", "message": "这套规则要掷 1d100" },
  "levels": [
    { "name": "critical", "label": "大成功", "success": true, "condition": "roll <= 5" },
    { "name": "success",  "label": "成功",   "success": true, "condition": "roll <= target" },
    { "name": "failure",  "label": "失败",   "success": false, "condition": "true" }
  ]
}
```

条件里可以用 `+ - * / // %`、比较（`< <= > >= == !=`）、`and` / `or` / `not` 与括号
（`//` 是向下取整）。**最后一级必须无条件匹配**（`"condition": "true"`），
写漏了或者顺序排错了，加载时会直接告诉你 —— 不会等玩家掷出那个点数才暴露。

**结束这一局**：敲 `/能力 卸载 trpg` 交还主流程，机器人变回普通群友。
一局跑完的记录留在 `data/trpg/<群号>.json` 里（人物卡、场景、旗标、剧本快照、最近 60 条日志），
下次加载还在 —— 想重开一局让 DM 调 `campaign` 的 `action=start` 带 `restart`。

**DM 能做的事**（也就是它手里的工具）：开局（可指定剧本与规则表）、建/改人物卡、改场景与剧情旗标、揭示暗线、掷骰、检定、发言。
它**没有**记忆工具、没有联网、没有画图 —— 接管模式下这些都被换掉了，这也是它只该在一个群里开的原因。

> ⚠️ 跑团**默认是关的**，而且开了也**不会自动接管任何群** —— 必须敲 `/能力 加载 trpg`
> 或者写进配置。跑团比搜图/转写/出图更重：它换掉的是机器人在这个群里的整个人格。

### 存储上限与手动清理

两类运行数据会一直增长，各有**一个上限旋钮**（都在设置页「存储」一段里）和**一个手动清理入口**：

| 数据 | 上限（0 = 不限） | 超限时 | 手动清理位置 |
| --- | --- | --- | --- |
| 消息存档 | `单个会话最多保留 N 条存档` | 每次写入丢掉最老几条 | 存档页 →「清空本会话存档」 |
| 会话记录 | `最多保留 N 个会话记录文件` | 会话结束时删掉最老的文件 | 会话页 → 每行的 `×` |
| 群友记忆 | （没有条数上限） | — | 记忆页 →「清空本会话记忆」，或点某个人的「删」 |

**两个上限容易搞混，它们管的是完全不同的东西**：

- **单个会话最多保留 N 条存档** = 磁盘上的存档条数。机器人自己的发言、历史摘要、人工备注**都算在内**。
  超限丢掉的**不可恢复**；想清理已有的存量用它下面的手动入口。
- **最多保留 N 个会话记录文件** = 每次运行的"过程留档"（请求/响应），在会话页看。
  **它不影响消息存档和记忆** —— 删掉的只是那次运行的过程。

这两个都**默认 0（不限）**，也就是保持原行为：不配置就永远不会自动删你的数据。要限制就得自己填。

**删除操作的后果**（都不可从界面撤销，所以每个都会先弹确认）：

- **清空本会话存档**：删掉这个会话的存档文件、历史摘要、以及压缩后的冷归档。
  删除前会自动留一份最近一次的备份（`data/messages/<会话>.json.removed.bak`）。
- **删单条会话记录**：只删这一次运行的记录。不影响消息存档和记忆。
  **正在运行的会话删不掉**（它还在写这个文件，删了会被收尾时原样写回来），会提示等它结束。
- **清空本会话记忆**：删掉这个会话下**所有群友**的全部印象。只想去掉某个人，
  用那个人那一行的「删」按钮（成员级），两个粒度别混。

三个删除动作完成后，**列表与右侧详情会一起重新加载**——否则右侧会继续显示那个
已经不存在的会话，看起来就像"删了没反应"。

**删到一条不剩时会整份删掉**：存档/记忆被清空之后，那份文件（或记忆目录）本身也会被删除，
而不是留一个"看似有、点开全空"的空壳。所以清空之后这个会话会从对应列表里消失。

> 想重新把它纳入管理，用列表右上角的**「＋ 新建会话」**：填群号或 QQ 号
> （也可以点「从列表里选…」拉群/好友列表），就会为它建出**空存档与空记忆**，
> 之后你可以在两个页面里各自往里加备注 / 印象。已经存在的话不会被覆盖（幂等）。

> 会话记录的删除**不影响今日用量统计**：已结束会话的 token 在结束时就已经累加进
> `usage-today.json` 这个独立聚合了，删掉历史会话文件不会把账弄对不上。

### 漫画：先搜索，再决定下载

群里说「想看 XXX」时，机器人先**搜索**出候选，再由你确认要哪一本，最后才**下载**。

**搜索**（`search_jmcomic`）：按关键词或标签查，只返回 ID、标题、标签的列表，
**不会下载任何东西**，可以放心反复搜。

| 参数 | 说明 |
| --- | --- |
| `query` | 搜索词。作品名、作者名、角色名都能搜到；按标签搜写 `tag:标签名`，例如 `tag:巨乳` |
| `mode` | `keyword`（关键词，默认）/ `tag`（标签）/ `author`（作者）/ `work`（作品）/ `actor`（角色）。用 `tag:` 前缀时不必再填 |
| `orderBy` | `latest`（最新，默认）/ `view`（最多观看）/ `picture`（最多图片）/ `like`（最多点赞）/ `score`（评分）/ `comment`（最多评论） |
| `page` / `limit` | 页码（从 1 开始）与返回条数（默认 10，最多 40） |

**下载**（`download_jmcomic`）：拿到 ID 后再调它，行为与从前一致——入队、生成 PDF、
上传到当前群聊或私聊，完成后以【漫画下载结果】回流。**也可以直接敲 `/漫画 <ID>`**（2026-10 新增）：
已经知道 ID 时不必先跟机器人绕一圈，命令路径与工具路径共用同一套去重（同一人短时间内不能重复提交）、
同一套调用额度，完成后同样回流入窗让模型补一句话。**失败也一样**：没下成是【漫画下载失败】、
PDF 发出去了但没能确认是【漫画发送未确认】（那份文件很可能已经在群里，别急着重发），
两种情况都由模型自己交代，而不是机器人贴一句机器味的报错。

> **搜索和下载是刻意分开的两个工具。** 搜索是廉价的只读操作；下载要统计页数、拉全部图片、
> 导出 PDF、上传群文件（30 分钟超时，且**不可撤销**）。合成一个动作就等于"机器人猜一个关键词"
> 触发一次完整下载。所以 system prompt 里明确要求：**搜到之后不要自己挑一本下载**，
> 而是把候选标题（带 ID）说给你听、问你选哪本。这是刻意的人工闸门，不是没做完。

搜索结果是**同步**返回的（约 1～2 秒），不需要等回流。没搜到时机器人会如实说没找到、
换个词再试，**不会编造 ID**。

排序与搜索范围都走**白名单**（`latest`/`view`/… 而不是直接透传库的魔法值）：
这些值会拼进查询串，透传等于让模型决定 URL 内容。

### 读文件（PDF / Word / txt / md）

群友把一份文件发到群里、让你看看里面写了什么时，机器人能**把正文读出来**：

- 支持 **`.pdf` / `.docx` / `.txt` / `.md`**。格式按**文件内容**认，不按后缀 —— 后缀写错了也读得出来。
- 你在群里看到的是 `[文件剧本.pdf]` 这样的占位符，**正文要机器人去读**。直接说"看看这个文件"就行，
  也可以引用那份文件所在的（或引用它的）消息再说一句。
- 也可以给一个**网页上的文件直链**（`.pdf` / `.docx` 的 http(s) 地址），它会下载下来读。
- 正文字数有上限；超了会告诉模型"共 N 字"，那时它只看到开头。
- **扫描件读不出来**：整页是图片的 PDF 抽不出文字（那种要用看图那条路）。旧版 `.doc` / `.xls` 也不行
  —— 用 Word / WPS 另存为 `.docx` 再传。
- 没有开关，装好就能用。**只有 PDF 需要额外的 Python 库**（`pypdf`），见下面「Python 工具」；
  `.docx` 与纯文本不需要。

### Python 工具

项目里的 Python 工具都放在 `python-tools/`，**共用同一个解释器**：

| 脚本 | 用途 |
| --- | --- |
| `jmcomic_download.py` | 搜索漫画（`search` 子命令）与下载漫画并生成 PDF |
| `pic_image_search_worker.py` | 搜图 worker（PicImageSearch 常驻进程） |
| `document_extract.py` | 把 pdf / docx / txt / md 抽成纯文本（`read_document` 工具与跑团剧本都用它）|

> 只有 `document_extract.py` 里的 **PDF** 需要外部库（`pypdf`）；`.docx` 与纯文本走 Python 标准库，
> 所以**没装依赖时读 txt / md / docx 照常**，只有 PDF 会明确告诉你"去装 pypdf"。

依赖合并成一份，装一次即可（把 `<python>` 换成下面配置的那个解释器）：

```bash
<python> -m pip install -r python-tools/requirements.txt
```

解释器在设置页「Python 工具」里填，也可以直接改 `data/config.json` 的顶层 `python.path`。
填的是**解释器可执行文件**的完整路径，留空则自动探测：

```json
{
  "transcription": { "ffmpegPath": "/usr/bin/ffmpeg" },
  "python": { "path": "/opt/conda/envs/my_bot/bin/python" }
}
```

`python.path` 留空时的探测顺序：**随包内置的运行时**（只有打包时带了 `--with-python` 才有这一层）→
`QQ_AGENT_PYTHON` → `conda run`（用哪个环境见下面那一栏 conda 环境：环境名走 `-n`、环境目录走 `-p`、
留空用 conda 当前环境）。设置页的「测试解释器」会告诉你**当前生效的是哪一层**与完整命令。

⚠️ **内置运行时排在链首**：包里有它时，这一页填的 `python.path` **不会生效**（内置那一份带着装好的依赖，
是唯一"确定能用"的。要换成自己的解释器，删掉 `resources\app\python-runtime\` 目录即可）。

> 旧版本用的 `jmcomic.pythonPath` 已并入 `python.path`。老配置**会自动迁移**，不必重填；
> 首次保存设置后旧键会从 `config.json` 里移除。
> 更早的环境变量别名 `JMCOMIC_PYTHON` 已于 2026-09-29 **正式废弃**（两个工具共用一个解释器，
> 各给一个变量的结果是「装了 A 库的那个环境跑不了 B」），不再参与探测。

填完不确定对不对，用同一页的两个按钮自查（两者都是**先保存本页、再按已保存的值探测**）：

- **测试解释器**：显示当前生效的是哪一层来源、实际用的命令、解释器版本，以及 `PicImageSearch` 与
  `jmcomic` 能否 import。路径填错时会直接告诉你「这个路径下没有文件」，不必等搜图失败再反推。
- **跑一遍依赖自检**：用配置的解释器执行 `python-tools/pic_image_search_worker.py --self-check`，
  把输出原文（含 stderr）显示出来。**这才是搜图依赖的权威检查**——库版本、引擎类名与字段是否与
  worker 的假设一致，只有它会说。

### 桌面端

`npm start` 启动的桌面端带托盘运行与明暗主题；关闭窗口默认收到托盘而不是退出，退出菜单会等待后台任务
与传输层关停完成。仅需后端时用 `npm run server`，它不依赖 Electron。

⚠️ 在 VS Code 的**集成终端**里跑 `npm start` 会以 `cjsPreparseModuleExports` 的 TypeError 崩溃：
VS Code 给终端注入了 `ELECTRON_RUN_AS_NODE=1`，Electron 于是被当成纯 Node 启动。用系统终端、双击
`启动QQ机器人.bat`，或先 `unset ELECTRON_RUN_AS_NODE`（PowerShell：`Remove-Item Env:ELECTRON_RUN_AS_NODE`）。

### 打包成桌面应用（绿色版）

想把项目打成"解压即用、用户不需要装 Node"的桌面应用：

```bash
npm run dist:desktop            # 清空 dist 重新编译并打包，产物在 release/qq-agent-<版本>-<平台>-<架构>/
npm run dist:desktop -- --zip   # 顺手压一个 zip（发给别人用）
```

产物目录里双击 `QQ Agent.exe` 就能运行：数据（含 API Key）第一次启动时自动建在 exe 旁边的 `data/`，
备份与换机器都是整个目录搬走；**打好的包里不含任何数据与密钥**。几条约定：

- **白名单打包**：只搬 `dist/ ui/ electron/ assets/ python-tools/` 与生产依赖闭包（js-yaml、node-cron、
  undici、ws），`data/`、`snowluma/logs/`、`.env`、日志、`*.pyc` 一律进不来。
- **不打 asar**：`python-tools/*.py` 要 `spawn` 给 Python、SnowLuma 目录里的可执行文件要拉起、
  `ui/` 与 `data/` 必须是真文件。
- **打完自动校验**：必需文件清单、`src/**/*.ts` ⇄ `dist/**/*.js` 对账、敏感文件扫描，再用产物里那份
  `dist/` 真跑一遍 `createApp → start → stop`（数据目录指向临时目录，绝不碰真实 `data/`）。
- **SnowLuma 是可选的第三方组件**（`snowluma/` 本来就被 `.gitignore` 挡着）：本机有就一起打进去，
  没有就跳过，使用者自己放到 `resources\app\snowLuma\` 即可被识别（`--with-snowluma` 强制、
  `--no-snowluma` 跳过）。
- **`--with-python` 让包内自带一份最小 Python 运行时**（搜图与漫画不必让用户自己装 Python）：
  默认从 python-build-standalone 拉一份当前平台的最小发行版、剪掉 test/tkinter 之类无关的东西，
  再 `pip install -r python-tools/requirements.txt` 装进**那一份**里（装不上只警告，使用说明里给了补装命令）。
  解析顺序是「**内置运行时 > 用户配的 `python.path` > `QQ_AGENT_PYTHON` > 本机 conda 回退**」——
  带了内置运行时的包里，设置页那一栏填什么都不生效（它带着装好的依赖，是唯一"确定能用"的那一份；
  要换成自己的解释器就删掉 `resources\app\python-runtime\` 目录）。离线打包用
  `--python-dist <本机目录或压缩包>`，装依赖用 `--python-no-deps` 跳过。
- exe 的文件图标仍是 Electron 的（换 PE 资源图标需要 rcedit，脚本不做）；窗口与托盘图标用的是
  `assets/icon.png`，不受影响。

完整选项见 `node scripts/build-desktop.mjs --help`。

## 开发与验证

改了源码要重新编译（开发时建议开 watch，它会一直盯着 `src/`）：

```bash
npm run dev          # tsc --watch
npm run typecheck    # 只检查类型，不产物
npm run build        # 编译一次
npm run check        # typecheck + 分层检查 + 全部测试套件
npm test             # 先 build，再跑 tests/ 下的断言套件
npm run test:all     # 含打印式诊断套件
npm run dist:desktop # 打包成绿色版桌面应用（见上一节）
```

`npm test` 加载的是 `dist/`，所以别拿未 build 的结果判断源码行为。

依赖：Node ≥ 20，`npm ci` 需要能访问 npm 源（会装 Electron，约 300MB）。打包桌面版用
`npm run dist:desktop`（它会替你把生产依赖与 Electron 运行时一起搬进产物）；只想手工做一个仅运行后端的
发布目录时，才需要自己 `npm run build` 后在发布目录 `npm ci --omit=dev`。

完整的调用链、提示词结构、上下文语义与维护约束见 [当前架构与维护指南](docs/ts-migration-plan.md)；
事件、端口与长期任务的设计见 [注册层设计](docs/global-registry-design.md)。

## 数据与隐私

所有运行数据默认保存在本地 `data/` 目录（该目录不被 Git 跟踪），包括 API Key、聊天存档、会话记录、
成员记忆与白名单——这些都可能包含敏感信息。

- 不要提交 `data/`、日志、登录态或第三方协议端配置。
- 将代码分享或推送到公开仓库前，先执行只读扫描：

```bash
node scripts/sanitize-release.mjs --scan
```

- 如需清理本地部署数据，请先预览清理范围（第二条会清理 Key、白名单、存档和登录态，执行前自行备份）：

```bash
node scripts/sanitize-release.mjs --dry-run
node scripts/sanitize-release.mjs
```

## 使用限制

请勿将本项目用于：

- 未经许可收集、公开或分析他人的聊天内容
- 群发广告、刷屏、骚扰、欺诈或冒充他人
- 绕过平台风控、访问控制或服务限制
- 传播违法、有害或侵犯他人权益的内容
- 任何违反平台协议或当地法律法规的场景

机器人输出由外部模型生成，可能存在错误、偏见或不当内容。请保留人工监督，不要将输出直接用于医疗、
法律、金融等高风险决策。
