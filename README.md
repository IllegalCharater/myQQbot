# myQQbot

基于 Electron、Node.js 与 OneBot v11 的本地 QQ AI 机器人实验项目，可接入 OpenAI 兼容接口，并通过桌面控制台管理模型、会话、记忆和消息响应策略。

> **学习用途声明**
>
> 本项目仅用于个人学习、技术研究与交流，不用于商业运营，也不鼓励将其用于批量营销、骚扰、垃圾信息、绕过平台限制或其他违规行为。使用者应自行遵守 QQ 平台规则、所接入模型服务的使用条款以及所在地法律法规。因使用、修改或分发本项目造成的账号限制、数据损失、费用支出或其他后果，由使用者自行承担。

## 主要功能

- 通过 OneBot v11 正向 WebSocket 接收和发送 QQ 消息
- 支持 OpenAI 兼容的模型 API，可配置多个模型服务
- 支持群聊、私聊、@ 响应、关键词响应和概率响应
- 使用新消息窗口、分档历史深度与统一字符预算控制上下文成本
- 保存本地消息存档、会话记录和群友长期记忆
- 支持图片理解、网页搜索、表情包、引用、@ 和戳一戳
- 可选的视频 URL 转写：流式提取音频并调用腾讯云录音文件识别极速版
- 统计模型调用量、Token 用量和估算费用
- 提供 Electron 桌面控制台、托盘运行和明暗主题

## 工作方式

1. OneBot 协议端将新消息写入本地存档，同时推入对应会话的新消息窗口。
2. 调度器使用全部未处理消息判断艾特、关键词、概率或全量响应，并按触发原因选择窗口之外的历史深度。
3. 提示词分层注入历史摘要、已读历史、本轮新消息、相关成员记忆和表情目录；当前窗口不会再次进入历史区。
4. 统一字符预算优先保留本轮新消息和决策指令，超限时收缩可选背景，避免多个独立上限叠加失控。
5. 同一次运行可以多轮调用工具；会话结束后不保留模型侧对话历史，长期信息单独落入摘要或成员记忆。
6. 处理期间收到的新消息留在窗口中，当前运行结束后由下一轮继续处理。

完整的调用链、提示词结构、动态上下文和维护约束见 [当前架构与维护指南](docs/ts-migration-plan.md)。

所有运行数据默认保存在本地 `data/` 目录中，该目录不会被 Git 跟踪。

## 环境要求

- Windows
- Node.js 20 或更高版本
- 一个兼容 OneBot v11 正向 WebSocket 的 QQ 协议端

## 安装与启动

按锁文件安装依赖并首次编译（源码在 `src/`，运行时跑的是 `tsc` 的编译产物 `dist/`）：

```bash
npm ci
npm run build
```

启动桌面端：

```bash
npm start
```

`npm start` / `npm run server` 会自动先编译一次（npm 的 `pre*` 钩子），所以日常不必手动 build。

也可以双击项目根目录中的 `启动QQ机器人.bat`（它直接起 `node_modules` 里的 Electron，
跑的就是 `dist/`——所以**首次双击前要先 `npm ci && npm run build`**，
或者用 `npm start` 让它自己编译）。

仅启动 Web 服务：

```bash
npm run server
```

随后访问 `http://127.0.0.1:3210`。

改了源码要重新编译（开发时建议开 watch，它会一直盯着 `src/`）：

```bash
npm run dev          # tsc --watch
npm run typecheck    # 只检查类型，不产物
npm test             # 先 build，再跑 tests/ 下的套件
```

依赖：Node ≥ 20，`npm ci` 需要能访问 npm 源（会装 Electron，约 300MB）。制作仅运行后端的发布目录时，应先执行 `npm run build`，再在发布目录使用 `npm ci --omit=dev`；TypeScript 只参与构建，不需要随运行包安装。

## 基本配置

首次启动后，在控制台中依次完成：

1. 填写模型服务的 Base URL 和 API Key。
2. 获取并选择要使用的模型。
3. 配置 OneBot WebSocket 地址。
4. 选择允许机器人工作的群聊或好友白名单。
5. 根据需要调整响应档位、关键词、人设和搜索服务。

聊天设置中几个容易混淆的参数：

- “动态上下文窗口”只限制一次放入【本次唤醒】的新消息数量。
- “历史消息深度”独立控制窗口之前读取多少条记录，不受艾特、关键词、随机或响应档位影响。
- 当前窗口最早一条消息是历史边界：窗口内容只进【本次唤醒】，独立历史只从边界之前读取。
- 响应档位只保存滑条位置；档位编号和随机概率由程序运行时计算，避免多份配置互相冲突。
- 所有发送统一使用“每分钟最多发送”这一项；回复态触顶时可按设置短暂等待，不再另设一套回复态频率。
- “单次提示词统一字符预算”控制完整 user prompt；`0` 表示不限，默认 32000 字。
- 历史摘要字数是摘要通道自己的候选上限，最终仍受统一字符预算约束。

请从低频响应开始测试，确认行为符合预期后再逐步开放使用范围。

### 图片来源识别（可选）

设置页的“图片来源识别”默认关闭。开启后，模型可以调用 `reverse_image_source` 工具，让群友发的图去
trace.moe（动画截图 → 番名 / 集数 / 时间点）和 SauceNAO（二次元插画 → 画师 / 作品 / 来源站点）查出处。
是否该查由模型结合上下文判断，代码不做关键词拦截；工具结果是第三方匹配，只会被表述为“可能来源”，
且原图不会被交给大模型。

SauceNAO 需要 API Key，只能从设置页填写（输入框只允许写入或替换，服务端不会把原值返回浏览器；
未配置时该 provider 会被跳过，只走 trace.moe）。

两个第三方接口都有配额（SauceNAO 免费额度尤其紧），因此配置里有“每群每小时上限”（默认 5）与
“全局每日上限”（默认 30）两个调用闸门，超限时工具直接失败并告知原因。闸门只统计发起了几次查询，
命中内存缓存的重复图片同样计数。

识别失败时工具会说明**具体原因**（图片下载失败 / 查询超时 / 第三方接口没有返回结果 / 队列已满），
不再是笼统的“没成功”，同一句话同时写进程序日志（`[image-source] …`），排查时以日志里的原因为准。
如果反复是查询超时，可以在设置页调大“总任务超时”（默认 35000 毫秒，它要同时容纳图片下载与
两个第三方接口的响应）。

### 每日全网热搜播报（可选）

设置页的“每日热搜播报”可配置启用状态、北京时间、目标白名单群、每次条数、平台范围和是否附链接。
数据来自极数本源的[全平台热搜聚合接口](https://apizero.cn/marketplace/hot-search/sub/all)；默认关闭、每天
09:00（`Asia/Shanghai`）、10 条且不附外链。目标群只会从当前 OneBot 群列表与发送白名单的交集中选择，
实际发送仍走统一的 `SendQueue` 限频与长度保护。

API Key 可在设置页填写，也可沿用项目的 systemd 环境注入方式：

```ini
Environment="HOT_SEARCH_API_KEY=<sk_live_xxx>"
```

未配置 Key 时仍会按接口文档尝试匿名调用，但匿名额度和 QPS 较低。Key 只通过
`Authorization: Bearer <API Key>` 请求头发送，不进入 URL、日志或控制台配置响应。任务元数据保存在
`data/hot-search-state.json`，只记录日期、状态、条数、目标群和脱敏错误摘要，不保存榜单正文或外链；
服务重启后会据此避免同一天重复播报。服务错过当天计划时刻不会补发，可在设置页查看原因或手动播报。

除定时播报外，模型还有一个只读工具 `get_hot_search`：群友问“今天有什么热搜”时它会自己去取榜单，
取到的是已排版好的分页文本，**要不要发、发几条由模型自己决定**（工具不会自动发送任何东西）。
因此启用开关但**不选目标群**，就是“只让模型按需查、不每天播报”的组合——定时任务在目标群为空时不会排定。

### 视频 URL 转写（可选）

群聊或私聊发送 `/转写 <视频URL>` 后，机器人会立即回执任务号，再由单并发后台队列完成
FFmpeg 音频提取与腾讯云录音文件识别极速版请求。该命令只接受公网 `http://` / `https://`
地址；本机、内网、链路本地、云元数据地址以及重定向到这些地址的请求都会被拒绝。

B 站普通公开视频可直接传 `bilibili.com/video/...` 或 `b23.tv/...` 链接，也可以回复一张 B 站
视频卡片并发送 `/转写`。卡片链接的识别不挑形态：老式新闻卡、App 分享出来的小程序卡，以及协议端
下发成 `xml` 的分享卡都能取到地址（不同形态的链接藏在不同字段里，只认其中一种就会出现“卡片看着
有链接、机器人却说没有”）。解析层会在任务真正执行时取首个分 P 的短时效音频地址，再交给同一套
安全代理和 FFmpeg；单独转发卡片不会自动产生转写费用。第一版不携带 B 站登录 Cookie，因此番剧、
课程、地区/登录受限内容不在支持范围内。

当前实现调用极速版独立 HTTPS 接口，将临时 MP3 作为二进制请求体直接上传，不经过 COS，也不创建
公开音频 URL。单音频按官方限制最多 2 小时且不超过 100 MiB；配置中的时长和大小只能进一步收紧。
完整视频不会先下载落盘：FFmpeg 只访问进程内的本地安全代理，临时 MP3 与长结果文本在任务结束后删除。

除了 `/转写` 命令，模型也可以自主调用 `transcribe_video` 工具：群友说“这视频讲了啥”时由模型判断要不要转，
入参可以是视频 URL，也可以是含视频（含 B 站卡片）的消息 id。工具只负责入队并立即返回，识别文本由后台
队列在完成后自动发到原会话，**模型不会干等**，也不会重复发言。因为转写按次计费，这条模型自主路径受设置页
“每群每小时上限”（默认 3）与“全局每日上限”（默认 10）约束，超限时工具直接失败并说明原因；
`/转写` 命令是人明确要求的，不受这两项限制。

管理界面的“音视频转写”页可以编辑功能开关、AppID、本地工具和任务限制。SecretId/SecretKey
输入框只允许写入或替换，服务端不会把原值返回浏览器；生产环境仍建议通过 systemd 环境变量注入：

```ini
Environment="QQ_AGENT_TRANSCRIPTION_ENABLED=true"
Environment="TENCENTCLOUD_APP_ID=<your-app-id>"
Environment="TENCENTCLOUD_SECRET_ID=<your-secret-id>"
Environment="TENCENTCLOUD_SECRET_KEY=<your-secret-key>"
Environment="FFMPEG_PATH=/usr/bin/ffmpeg"
```

`TENCENTCLOUD_APP_ID` 是腾讯云账号的数字 AppID；运行身份需要录音文件识别极速版权限。日志只记录
任务 ID、状态、音频大小、耗时和错误码，不记录原始 URL、请求签名、识别文本或凭证。

FFmpeg 路径由 `transcription.ffmpegPath` 读取。漫画下载使用的 Python 解释器可在 `data/config.json`
中显式指定；`pythonPath` 留空时继续使用原有的 `JMCOMIC_PYTHON`、本机环境和 conda 回退逻辑：

```json
{
  "transcription": { "ffmpegPath": "/usr/bin/ffmpeg" },
  "jmcomic": { "pythonPath": "/opt/conda/envs/my_bot/bin/python" }
}
```

## 数据与隐私

- API Key、聊天存档、记忆和会话记录可能包含敏感信息。
- 不要提交 `data/`、日志、登录态或第三方协议端配置。
- 将代码分享或推送到公开仓库前，请先执行只读扫描：

```bash
node scripts/sanitize-release.mjs --scan
```

如需清理本地部署数据，请先预览清理范围：

```bash
node scripts/sanitize-release.mjs --dry-run
node scripts/sanitize-release.mjs
```

第二条命令会清理 Key、白名单、存档和登录态，执行前请自行备份需要保留的数据。
