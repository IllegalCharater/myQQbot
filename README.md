# myQQbot

基于 Electron、Node.js、OneBot v11 与 OpenAI 兼容接口的本地 QQ AI 机器人。
后端是严格 TypeScript（运行 `dist/`），前端是不打包的原生 ES Module，全部运行数据落在本地 `data/`。

> **学习用途声明**
>
> 本项目仅用于个人学习、技术研究与交流，不用于商业运营，也不鼓励将其用于批量营销、骚扰、垃圾信息、绕过平台限制或其他违规行为。使用者应自行遵守 QQ 平台规则、所接入模型服务的使用条款以及所在地法律法规。因使用、修改或分发本项目造成的账号限制、数据损失、费用支出或其他后果，由使用者自行承担。

本项目在既有开源项目基础上学习修改而来，请优先了解并尊重原项目作者及其许可：

- 原始项目：[Derpyu520/qq-bridge](https://github.com/Derpyu520/qq-bridge)
- 此前的 QQ Agent 项目：[Kondius/qq-agent](https://github.com/Kondius/qq-agent)

本仓库中的修改不代表上述项目作者的立场。涉及第三方组件时，以其各自的许可证和使用条款为准。

主要能力：群聊/私聊的艾特、关键词、概率与全量响应，多轮工具调用，图片理解，表情包，网页搜索，
视频 URL 转写，以及可选的图片溯源、每日热搜播报；控制台提供模型、会话、记忆、消息策略与用量的管理界面。

## 环境要求

- Windows（Linux 下可用 headless 的 `npm run server`）
- Node.js 20 或更高版本
- 一个兼容 OneBot v11 正向 WebSocket 的 QQ 协议端
- 一个 OpenAI 兼容模型 API
- 可选：视频转写需要 FFmpeg 并开通腾讯云录音文件识别极速版；图片溯源需要 Python（见下方「Python 工具」）

SnowLuma 可作为协议端使用，但它是独立第三方项目，不包含在本仓库中，并受其自身 EULA 和使用条款约束。

## 安装与启动

按锁文件安装依赖并首次编译（源码在 `src/`，运行时跑的是 `tsc` 的编译产物 `dist/`）：

```bash
npm ci
npm run build
```

启动桌面端：

```bash
npm start
```

也可以双击项目根目录的 `启动QQ机器人.bat`（它直接起 `node_modules` 里的 Electron，跑的就是 `dist/`——
所以**首次双击前要先 `npm ci && npm run build`**，或者用 `npm start` 让它自己编译）。

仅启动 Web 服务（不开桌面窗口）：

```bash
npm run server
```

`npm start` / `npm run server` 会自动先编译一次（npm 的 `pre*` 钩子），所以日常不必手动 build。
随后访问 `http://127.0.0.1:3210` 打开控制台。

## 首次配置

启动后打开控制台，按顺序完成下面四件事：

1. **模型 API**：填 Base URL 与 API Key，点「获取列表」拉取模型并选择要用的那个。可以配多个提供商，
   每个模型有独立的输入/输出价格，供成本核算使用。
2. **OneBot 连接**：填协议端的 WebSocket 地址（以及需要的 Access Token）。地址变更保存后会立即重连；
   用 SnowLuma 时可以在同一页启动它、查看日志与 WebUI 地址。
3. **聊天白名单**：选择允许机器人工作的群聊或好友。白名单为空时可用「允许全部」临时放开，
   建议先只放一个测试群。
4. **响应与上下文**：在聊天设置里调整响应档位、关键词、人设与上下文参数。

### 聊天与上下文参数

聊天设置里有几个容易混淆的项：

- **动态上下文窗口**只限制一次放入【本次唤醒】的新消息条数，`0` 表示不限。
- **历史消息深度**独立控制窗口之前读取多少条记录，不受艾特、关键词、随机或响应档位影响。
- 当前窗口最早一条消息是历史边界：窗口内容只进【本次唤醒】，独立历史只从边界之前读取。
- **响应档位**只保存滑条位置，档位编号与随机概率由程序运行时计算，避免多份配置互相冲突。
- 所有发送统一使用**每分钟最多发送**这一项；回复态触顶时可按设置短暂等待，不再另设一套回复态频率。
- **单次提示词统一字符预算**控制完整 user prompt，`0` 表示不限（默认 32000 字）。超限时依次收缩
  表情目录、摘要、记忆与已读历史，本轮新消息不会被静默截断。
- **历史摘要字数**是摘要通道自己的候选上限，最终仍受统一字符预算约束。

请从低频响应开始测试，确认行为符合预期后再逐步放开。

## 可选功能

### 网页搜索与收藏夹

联网搜索**默认开启**，模型可以调用 `web_search`（搜索）与 `web_fetch`（读正文，≤2 万字符）。
搜索后端在设置页「搜索服务」里选：默认是免 Key 的 **Bing 网页解析**，也可以换成 DeepSeek 原生搜索、
智谱、博查、百度千帆、秘塔、Yandex 网页解析，或自行添加兼容 JSON / Bing 结果格式的自定义服务。

**Yandex** 这一路抓的是公开结果页（不需要 Key），但它有两个你应当知道的特性：**会被 CAPTCHA 拦**
（被拦时工具会明确说"要求人机验证"，而不是假装没搜到），以及 **Yandex 会改页面结构**。所以它的四个
选择器（结果容器类名、标题锚点类名、链接类名、摘要类名）都做成了设置页可改的字段：工具报"没有解析到
结果"时，把类名改成当前页面上的值即可恢复，不必等一次发版。搜索页地址也能换成 `yandex.ru` 等镜像。

**网页收藏夹**（同一页）用来告诉机器人「哪些站点是常看的」。**前三条都要填**：

| 字段 | 说明 |
|---|---|
| 枚举值 | 模型在 `web_search` 的 `site` 参数里传的就是它。只能是字母/数字/`-`/`_`（如 `wiki`、`news-yc`），**中文会被丢弃** |
| 网页地址 | 站点的域名（填整条网址也行，路径会被丢掉） |
| 用途 | **会随每轮提示词交给模型**，是它判断「该选哪一条」的依据 |
| 站内搜索地址（可选） | 见下。**想让"只在这个站里搜"真生效就必须填** |
| 结果容器类名（可选） | 该站结果块的类名；留空用通用解析 |

### ⚠️ 为什么「站内搜索地址」是必需的

实测 **Bing 对程序化请求完全忽略 `site:` 限定符**：带与不带的结果**逐字节相同**，换个必然被
收录的站点（如 zhihu.com）同样零命中；`cn.bing.com` 与 `www.bing.com`、中英文语言都试过，
行为一致。所以只填域名时，「限定在这个站里搜」**实际上没有生效**——收藏夹只影响排序与标记。

填了**站内搜索地址**才会真正去那个站自己的搜索页取内容（绕开搜索引擎）：

```text
https://zh.wikipedia.org/w/index.php?search={q}
https://your-docs.example.com/search?q={q}
```

`{q}` 是查询词占位符，**必须包含**，否则这一栏会被忽略（缺了它请求会打到搜索页首页、
返回"文不对题"的结果，比直接报错更难查）。留空则退回 `site:` 行为——对自建 SearXNG 等
仍认这个语法的服务有效。

**不知道填什么？点那一行右边的「检测」按钮。** 它会自动试常见的搜索入口
（`?q=`/`?query=`/`?search=`/`?keyword=`/`?wd=` × `/search` 与根路径），把可用的那个填进去。
判定方式不是"有没有抓到结果"，而是**减掉该站首页本来就有的链接后还剩几条**——因为真实搜索页
里满是导航链接，不减基线的话任何页面都"看起来有结果"（实测 Bing 的结果页对正常查询和乱串查询
都解析出 16 条，全是导航）。

检测**不保证成功**，三种情况会被拒并说明原因：
- 站点用 JavaScript 动态渲染结果（抓到的 HTML 里没有结果，如 MDN、PyPI）；
- 查询参数名不在这几个里，或结果在另一个主机上；
- 站点需要登录或被反爬拦截（反爬时连结果标记都会被去掉）。

检测不出来时，**最可靠的办法还是自己搜一次、把地址栏的 URL 抄进来**：在站内搜一个词，看地址栏
`?` 后面的部分，把查询词替成 `{q}` 即可。**注意不要**用文章路径（`/wiki/{q}` 是错的，
`/w/index.php?search={q}` 才对）。浏览器 `Ctrl+U` 看**源代码**（不是 F12 的 Elements）里搜不到
你要的词，就说明这个站是 JS 渲染、这条功能对它无效。

**结果容器类名**留空时用通用解析（会带上一些导航链接）；知道该站结果块的类名时填上更准
（如 GitHub 是 `search-title`、MediaWiki 是 `mw-search-result`）。工具报「站内搜索没有解析出结果」
就是在说这个站的页面结构变了，改这一栏即可。检测按钮在通用解析能判定时不会覆盖你手填的类名。

> ⚠️ 站内搜索**不能突破网络封锁**：如果那台机器访问不了某个站（例如境内访问 Wikipedia），
> 站内搜索同样连不上。工具会如实报出超时/连接错误，而不是假装"这个站没有内容"。

这份名单会随每轮提示词交给模型，于是模型每次搜索都可以自己决定「只在这个站点里搜」，传的那个值就是
**枚举值**（不是域名——服务端自己查表得出域名与站内搜索地址）。这是照「反向搜图」那套做的：
**该不该限定、限定在哪，是模型的判断**，代码只负责路由与校验。填错枚举值时会被明确拒绝，
并把可选值连同用途回给模型让它改对，而不是静默搜出一个空结果。

「收藏夹的默认行为」那个下拉只管模型**没有**指定站点时走哪条路：

- **优先在收藏夹里查，再补全网**（默认）——按关键词先问收藏夹，命中排在最前；
- **直接全网**——只有模型显式指定站点时才查收藏夹。

两种情况下，指定的站点里没有对应内容时都会自动补上全网结果，所以**收藏夹不会让搜索变窄到搜不到**。
模型显式指定站点时这个下拉不起作用。名单为空时一次额外的请求都不会发，行为与没有这个功能时完全一致。

> 从旧版本升级：原先的「每行一个域名」名单会**自动迁移**成三元组（域名 slug 化成枚举值，如
> `news.ycombinator.com` → `news-ycombinator-com`），**用途留空**。请在设置页把用途补上——没有用途时
> 模型拿到的只是一串生造的枚举值，它无法判断该用哪一条。

结果里带 `fromBookmark` 标记的条目来自收藏夹站点，标记的含义只是「这个站点被收藏」，
**不代表它更权威**——system prompt 里对模型说明了这一点，涉及事实仍要交叉验证。

同一页还有两个**联网调用闸门**：单会话每小时上限（默认 20）与全部会话每天上限（默认 200）。
`web_search` 与 `web_fetch` 是**同一份额度**（两者都算一次外部请求）。默认的 Bing 解析不直接产生费用，
所以这里的默认值比搜图/转写宽松，作用是压住刷屏；若换到按次计费的搜索服务，请自行调小。

### 图片来源识别

设置页的「图片来源识别」**默认关闭**。开启后模型可以调用 `reverse_image_source` 工具：

- **trace.moe**（动画截图 → 番名 / 集数 / 时间点）不需要 Key。
- **SauceNAO**（插画与漫画 → 画师 / 作品 / 来源站点）**需要 API Key**，只能在设置页填写（输入框只允许
  写入或替换，服务端不会把原值返回浏览器）。未配置时这一路被跳过。
- **百度识图**（一般向兜底）不需要 Key，可以在设置页单独关掉。

模型每次调用还会给出「这是哪类图」（`anime` / `manga` / `illustration` / `unknown`），查询按类型走：
**先问这个类型的专属引擎，没结果或超时了再用百度识图兜一次；判不出类型时直接走百度识图**。
是否该查由模型结合上下文判断，代码不做关键词拦截；原图不会交给大模型。

三个引擎各有自己的请求超时与结果条数。**「总任务超时」（默认 35000 毫秒）是整轮上限、也包含图片下载**，
别把各引擎的超时之和顶到这个数上——留给每个引擎的时间是从这条总线上按顺序分的。

两个第三方接口都有配额（SauceNAO 免费额度尤其紧），因此有**每群每小时上限**（默认 5）与
**全局每日上限**（默认 30）两个调用闸门，超限时工具直接失败并说明原因。

识别失败时工具会说明具体原因（图片下载失败 / 图片下载超时 / 查询超时 / 第三方接口没有返回结果 /
队列已满），同一句话也写进日志（`[image-source] …`）。其中「图片下载超时」与「查询超时」是两件事：
前者是那张图取不下来，后者才是接口慢。反复出现查询超时就调大「总任务超时」。

搜索由常驻的 Python worker 执行，开启前请先按下方「Python 工具」把依赖装到配置的解释器里。
设置页的「测试连接」可以分别探测三个引擎，用来确认配置与依赖是否就绪。

### 每日全网热搜播报

设置页的「每日热搜播报」可配置启用状态、北京时间、目标白名单群、每次条数、平台范围与是否附链接。
数据来自极数本源的[全平台热搜聚合接口](https://apizero.cn/marketplace/hot-search/sub/all)；
默认关闭，每天 09:00（`Asia/Shanghai`）、10 条且不附外链。目标群只会从当前 OneBot 群列表与发送
白名单的交集中选择，实际发送仍走统一的限频与长度保护。

API Key 可在设置页填写，也可沿用 systemd 环境注入：

```ini
Environment="HOT_SEARCH_API_KEY=<sk_live_xxx>"
```

未配置 Key 时仍会按接口文档尝试匿名调用，但匿名额度和 QPS 较低。Key 只通过
`Authorization: Bearer <API Key>` 请求头发送，不进入 URL、日志或控制台响应。任务元数据保存在
`data/hot-search-state.json`，只记录日期、状态、条数、目标群和脱敏错误摘要；服务重启后据此避免
同一天重复播报。错过当天计划时刻不会补发，可在设置页查看原因或手动播报。

除定时播报外，模型还有一个只读工具 `get_hot_search`：群友问「今天有什么热搜」时它会自己去取榜单，
**要不要发、发几条由模型自己决定**。因此启用开关但不选目标群，就是「只让模型按需查、不每天播报」的组合
——定时任务在目标群为空时不会排定。

### 视频 URL 转写

群聊或私聊发送 `/转写 <视频URL>` 后，机器人回执任务号，再由单并发后台队列完成 FFmpeg 音频提取与
腾讯云录音文件识别极速版请求。该命令只接受公网 `http://` / `https://` 地址；本机、内网、链路本地、
云元数据地址以及重定向到这些地址的请求都会被拒绝。

B 站普通公开视频可直接传 `bilibili.com/video/...` 或 `b23.tv/...` 链接，也可以回复一张 B 站视频卡片
并发送 `/转写`。解析层会在任务真正执行时取首个分 P 的短时效音频地址，再交给同一套安全代理和 FFmpeg；
单独转发卡片不会自动产生转写费用。第一版不携带 B 站登录 Cookie，因此番剧、课程、地区/登录受限内容
不在支持范围内。

实现上把临时 MP3 作为二进制请求体直接上传到极速版独立 HTTPS 接口，不经过 COS、不创建公开音频 URL；
完整视频不会先下载落盘，临时 MP3 与长结果文本在任务结束后删除。单音频按官方限制最多 2 小时且不超过
100 MiB，配置中的时长和大小只能进一步收紧。

除了 `/转写` 命令，模型也可以自主调用 `transcribe_video` 工具。`/转写` 是确定性快路径：立即回执，
完成后由后台队列**直接**把识别文本发到原会话，全程不经模型、零 LLM 成本。工具路径则由模型在这一次
运行里自己决定说不说话，识别结果作为一条【转写结果】异步进入会话上下文，到达时再跑一次模型来转述。
因为转写按次计费，这条模型自主路径受**每群每小时上限**（默认 3）与**全局每日上限**（默认 10）约束，
`/转写` 命令不受这两项限制。

凭证可在设置页填写，生产环境建议用 systemd 环境变量注入：

```ini
Environment="QQ_AGENT_TRANSCRIPTION_ENABLED=true"
Environment="TENCENTCLOUD_APP_ID=<your-app-id>"
Environment="TENCENTCLOUD_SECRET_ID=<your-secret-id>"
Environment="TENCENTCLOUD_SECRET_KEY=<your-secret-key>"
Environment="FFMPEG_PATH=/usr/bin/ffmpeg"
```

FFmpeg 路径也可以由设置页的 `transcription.ffmpegPath` 指定。SecretId/SecretKey 输入框只允许写入或
替换，服务端不会把原值返回浏览器。日志只记录任务 ID、状态、音频大小、耗时和错误码，不记录原始 URL、
请求签名、识别文本或凭证。

### Python 工具

项目里的 Python 工具都放在 `python-tools/`，**共用同一个解释器**：

| 脚本 | 用途 |
| --- | --- |
| `jmcomic_download.py` | 下载漫画并生成 PDF |
| `pic_image_search_worker.py` | 搜图 worker（PicImageSearch 常驻进程） |

依赖合并成一份，装一次即可（把 `<python>` 换成下面配置的那个解释器）：

```bash
<python> -m pip install -r python-tools/requirements.txt
```

解释器在设置页「Python 工具」里填，也可以直接改 `data/config.json` 的顶层 `python.path`。
填的是**解释器可执行文件**的完整路径，留空则自动探测：

```json
{
  "transcription": { "ffmpegPath": "/usr/bin/ffmpeg" },
  "python": { "path": "/opt/conda/envs/my_bot/bin/python" }
}
```

`python.path` 留空时的探测顺序：环境变量 `QQ_AGENT_PYTHON` → Windows 固定环境
`E:\anaconda\envs\my_bot\python.exe` → `conda run -n my_bot python`。

> 旧版本用的 `jmcomic.pythonPath` 已并入 `python.path`。老配置**会自动迁移**，不必重填；
> 首次保存设置后旧键会从 `config.json` 里移除。
> 更早的环境变量别名 `JMCOMIC_PYTHON` 已于 2026-09-29 **正式废弃**（两个工具共用一个解释器，
> 各给一个变量的结果是「装了 A 库的那个环境跑不了 B」），不再参与探测。

填完不确定对不对，用同一页的两个按钮自查（两者都是**先保存本页、再按已保存的值探测**）：

- **测试解释器**：显示当前生效的是哪一层来源、实际用的命令、解释器版本，以及 `PicImageSearch` 与
  `jmcomic` 能否 import。路径填错时会直接告诉你「这个路径下没有文件」，不必等搜图失败再反推。
- **跑一遍依赖自检**：用配置的解释器执行 `python-tools/pic_image_search_worker.py --self-check`，
  把输出原文（含 stderr）显示出来。**这才是搜图依赖的权威检查**——库版本、引擎类名与字段是否与
  worker 的假设一致，只有它会说。

### 桌面端

`npm start` 启动的桌面端带托盘运行与明暗主题；关闭窗口默认收到托盘而不是退出，退出菜单会等待后台任务
与传输层关停完成。仅需后端时用 `npm run server`，它不依赖 Electron。

## 开发与验证

改了源码要重新编译（开发时建议开 watch，它会一直盯着 `src/`）：

```bash
npm run dev          # tsc --watch
npm run typecheck    # 只检查类型，不产物
npm run build        # 编译一次
npm run check        # typecheck + 分层检查 + 全部测试套件
npm test             # 先 build，再跑 tests/ 下的断言套件
npm run test:all     # 含打印式诊断套件
```

`npm test` 加载的是 `dist/`，所以别拿未 build 的结果判断源码行为。

依赖：Node ≥ 20，`npm ci` 需要能访问 npm 源（会装 Electron，约 300MB）。制作仅运行后端的发布目录时，
应先执行 `npm run build`，再在发布目录使用 `npm ci --omit=dev`；TypeScript 只参与构建，不需要随运行包安装。

完整的调用链、提示词结构、上下文语义与维护约束见 [当前架构与维护指南](docs/ts-migration-plan.md)；
事件、端口与长期任务的设计见 [注册层设计](docs/global-registry-design.md)。

## 数据与隐私

所有运行数据默认保存在本地 `data/` 目录（该目录不被 Git 跟踪），包括 API Key、聊天存档、会话记录、
成员记忆与白名单——这些都可能包含敏感信息。

- 不要提交 `data/`、日志、登录态或第三方协议端配置。
- 将代码分享或推送到公开仓库前，先执行只读扫描：

```bash
node scripts/sanitize-release.mjs --scan
```

- 如需清理本地部署数据，请先预览清理范围（第二条会清理 Key、白名单、存档和登录态，执行前自行备份）：

```bash
node scripts/sanitize-release.mjs --dry-run
node scripts/sanitize-release.mjs
```

## 使用限制

请勿将本项目用于：

- 传播违法、有害或侵犯他人权益的内容
- 任何违反平台协议或当地法律法规的场景

法律、金融等高风险决策。
