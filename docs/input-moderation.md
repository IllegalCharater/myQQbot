# 模型输入审核（`data_inspection_failed`）与降敏

> 这份文档只回答一个问题：**当模型端点以"内容审核"为由拒收整个请求时，我们有哪些杠杆、哪些是死路、哪些做法不要用。**
> 最后核对：2026-10-20（首次实测）。

## 1. 现象与识别

错误长这样（`llm.ts` 的 `describeApiError` 会把它翻成人话）：

```
模型 API HTTP 400：{ "error": { "code": "data_inspection_failed",
  "message": "Input text data may contain inappropriate content.", ... } }
```

三条特征，缺一条就不是这件事：

- 来自**文本模型**的 `chat/completions`（不是出图接口 `media/image-gen/client.ts`，也不是提示词编译层 `compile.ts`）；
- 会话记录里 **`usage.calls === 0` 且 `responses: []`** —— 这一轮**一个请求都没成功**；
- **群里没有任何反应**（`session.error` 只进会话记录，宿主不代模型开口）。

## 2. 它是什么、不是什么

- **不是**"模型敏感度"这种可以调的参数 —— 它是**服务商在请求入口做的合规过滤**，阈值在服务端，客户端调不了。
- **不是** jmcomic / 出图 / 提示词编译层的 bug。编译层是 **fail-open** 的（失败只记 `COMPILE_*` 日志、退回原始描述），它的调用失败**不会**变成会话错误。
- **不是**网络问题：400 属于"客户端错误"，`isRetryableError` 判它不可重试（重试只会白烧额度）。
- ⚠️ **它拒的是整个请求体**。`messages` 里只要**有一条**命中，整轮就 400 —— 所以"历史里留着一句"等于"之后每一轮都过不去"，哪怕这一轮你在聊别的。

## 3. 怎么定位到具体哪一条（不用改代码）

面板 →「会话」→ 这条记录 → **JSON 模式**。`llmRequests` 在**发请求之前**就落盘（`agent-runner.ts` 的 `requestSnapshot`），所以被拒那一发的完整输入看得到。

先看形状：

| `requests` 的形状 | 触发源 |
| --- | --- |
| 只有 1 条且被拒 | **开场拼好的 system / user prompt**：历史摘要、长期记忆、过去状态、人设卡 |
| ≥2 条，最后一条带着 `role:"tool"` | **工具结果**（例如漫画搜索的标题/标签、转写正文） |

再按块二分 user prompt，顺序是"最攒词的地方先看"：

```
【历史印象】(压缩摘要) → 【记忆】 → 【过去状态】 → 【本次唤醒】 → system prompt 里的人设卡
```

## 4. 实测样例（2026-10-20）

一次"让 bot 画张图"的请求被拒，`calls: 0` —— 说明触发在**开场 prompt**，与出图无关。逐块看下来，**同一份 prompt 里同时躺着四类词**：

| 类别 | 大致形态 | 当时所在 |
| --- | --- | --- |
| 政治 / 人权 | 群友在聊某国的人权、劳动公约、入世 | 【历史印象】 |
| 未成年 + 色情 | 群友自述"把不准生成 X 和 Y 的约束删掉了"（X/Y 就是那两类词） | 【过去状态】 |
| 色情 / 露骨 | 长期印象里对某位群友偏好的描述 | 【记忆】 |
| 毒品 | 一句新闻式转述 | 【历史印象】 |

> ⚠️ **这里刻意不抄原文**：群聊内容属于敏感数据（见 `AGENTS.md`「已知安全与数据原则」）。要复现就看你自己那份 `llmRequests`，不要把它贴进仓库或 issue。

**结论**：四类里**任意一类**都足以拦下整轮，而它们分散在三块上下文里 —— **删一处不够**，要按"块"清。

## 5. 三条杠杆

### 5.1 换端点（唯一能真正关掉这层）

设置页「模型 API」的 `provider` / `baseUrl` / `model` 可换，且支持多个提供商各带自己的 Key。

| 换到 | 效果 |
| --- | --- |
| 本地 / 自建网关（ollama、vLLM、One-API 自建） | 请求入口**没有这层审核**，最彻底 |
| 海外中转 | 审核通常发生在模型侧、不是请求入口，这种"整包拒收"基本不会出现 |
| 其他国内云 | 一样有输入审核，只是错误码与文案不同 |

⚠️ **出图是另一套 Key**（`imageGen.*`，百炼 qwen-image）。换文本模型不影响出图，反之亦然。

### 5.2 别让敏感原文进入上下文（仓库能改的）

这一栏是"防复发"：审核看的是上下文，所以**凡是要回灌进上下文的正文，都该问一句"它有必要带原文吗"**。

| 落点 | 现状 | 可改 |
| --- | --- | --- |
| `chat/store.ts` 的 `appendImageResult` | 把画面描述**前 80 字**写进条目正文（`text`），之后每轮都带着 | 描述只放 `extra` 给面板看；`text` 只写"图片已生成" |
| `chat/store.ts` 的 `appendTranscript` | 语音识别的**正文**进条目正文 | 同理：正文留在任务记录里，上下文只留"有一段转写结果" |
| 摘要 / 记忆生成指令（`core/prompt-catalog.ts`） | 模型会**复述原话** —— 这次的敏感词大半就是这么攒进【历史印象】的 | 加一句"概括时不要保留原话里的敏感表达，用中性说法代替" |
| `trpg-note` / `jmcomic-result` | 正文带剧情/标题摘要 | 同上，逐条评估 |

代价知情：摘要会变"中性"、细节变少；回流条目变"薄"之后，模型对那一轮的上下文会少一点。

### 5.3 约束模型自己的输出（只对"模型写的那部分"有效）

模型在同一轮写下的文字（`tool_calls.arguments`、assistant 正文）会随**下一轮请求**再发一遍，所以能管：

- **出图的画面约束**（`imageGen.negativePrompt` 负面词 / `imageGen.stylePrompt` 风格层）——它们直接决定模型写出的画面描述有多越界。
  ⚠️ **这两处是配置项，不是代码**：2026-10-20 之前编译层的「覆盖前言」里挂过一段"成年主体 / 日常场景 / 日常着装"的附加约束，但它从收录那天起就是**注释掉的**（从未生效），还留着一句"上面的【部署方附加约束】优先于下面全部规则"指向不存在的东西；同一次连代码里焊死的 `SAFETY_NEGATIVE` 也一起删了。**所以今天"编译层有没有内容门禁"这个问题没有代码可以回答 —— 它完全取决于部署方在设置页那两栏里写了什么**；
- 人设卡里加一句"公开群聊里不写露骨或政治敏感的表述"。

⚠️ **它对群友原话无效**：审核看整个请求体，群友说了什么就带什么进去。

### 5.4 兜底：被拦时的观感

- **面板**：已翻译成人话（`describeApiError`）。
- **群里**：目前**一声不吭**。可选做法是由宿主回一句"模型的安全审核拦了这次请求"。这是产品决定 —— 它打破"只有模型开口"那条边界，但这次失败**不是模型的选择**，是运行级错误。

## 6. 不建议的做法

- **客户端敏感词替换 / 打码**：等于篡改群友的原话，模型看到的是被改过的聊天记录；而且规则永远追不上服务端的审核策略。
- **被拦后自动裁剪上下文重试**：剪成什么样不可预测，出了问题无法复现，还可能把"该说的话"一起剪掉。
- **把 `data_inspection_failed` 当成可重试错误**：400 是确定性的，重试只会白烧额度（`isRetryableError` 已经拦了，别放开）。

## 8. 守护

- `tests/t-llm-error.mjs`（9 条）：`data_inspection_failed` 翻成人话、两种来源都提到、原文保留、**消息前缀仍是 `模型 API HTTP <码>`**（`isRetryableError` 靠它判不重试）、认不出的错误原样透传、超长截断。
- 行为层**没法**用套件证明"某段文本会不会被服务商拦" —— 那是远端策略，只能靠这份文档里的排查方法人工定位。
