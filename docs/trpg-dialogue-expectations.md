# 跑团（TRPG）的对话预期

> 这份文档记录**当前实现**在群里长什么样：从装载到收团，逐幕列出。
> 读法上最要紧的一条在下一节 —— **代码说的与模型说的必须分开看**，混在一起会让这份文档变成一句空话。
> 最后核对：2026-10-19（与 `src/extra/trpg/` 的实现、`tests/t-trpg.mjs` 的 557 条断言同时）。
> P5（战斗）与 P6（战报导出）是 2026-10-17 补的两幕（第十一幕 / 第十二幕）；
> P7（剧情抽取管线 / 规则扩展）是 2026-10-19 补的 —— 它改了**第二幕**的形状，并新增**第十三幕**（`.trpg check`）。
>
> 设计动机、边界与守护空白在 `AGENTS.md`「跑团（TRPG）」；接管机制本身在 `docs/extras-design.md`。
> 这份文档只回答一个问题：**敲下去、说出去，群里到底会看到什么。**

## 怎么读这份东西

每一句都标了它是谁说的：

| 标记 | 含义 | 能不能当契约 |
| --- | --- | --- |
| **`[代码]`** | 由 TypeScript 逐字产出（命令回执、渲染、掷骰格式化） | ✅ 可以。改它 = 改行为，套件里有断言钉着其中一部分 |
| **`[模型]`** | 由模型生成 | ❌ 只保证**形状与硬约束**（比如"每轮收尾给 2-4 个选项"），措辞一字不保 |
| **`[内部]`** | 模型看得到、群友看不到（工具调用与结果、system prompt） | 形状是契约，正文不是 |

⚠️ **本文里的 `[代码]` 字面量是抄的，不是造的**。改完之后如果对不上，以代码与套件为事实，并**在同一次改动里**把这里一起改掉。复核方式见文末「怎么复核」。

**命令面**：跑团这一族以 **`.`** 开头（`.trpg`、`.pc`、`.combat`、`.log` 四族 + `.r`，2026-10-17 起；
`.combat` 与 `.log` 是 P5/P6 加的）；
主流程那几条仍是 `/`（`/转写` `/画` `/漫画` `/能力`）。

**场景**：群 `123456`，在白名单里；机器人显示名与 persona 名都叫「小鲸鱼」；设置页已经打开「跑团（TRPG）」并重启过（`extras.enabled.trpg`，**改完要重启**）。

## 第一幕：装载（全部零模型调用）

```
群友A：/能力
[代码] 小鲸鱼：扩展能力（✅ 已加载 / ○ 可用但未加载 / ✖ 停用）：
              - 跑团（TRPG）（trpg）○ 未加载　→ /能力 加载 trpg
              （……其余扩展各一行……）
              
              用法：/能力 加载 <id>、/能力 卸载 <id>
              （接管模式的扩展：在本群敲加载 = 只接管「本群」；别的群要各自敲一次，
               也可以写进设置文件让它开机就接管）

群友A：/能力 加载 trpg
[代码] 小鲸鱼：✅ 「跑团（TRPG）」已接管这个会话（下一轮运行生效）

群友A：.trpg status
[代码] 小鲸鱼：【跑团】这个群还没开局。按这个顺序来：

              1. 定模式（当前：DM 模式（跑团，我当主持人））
                 · `.trpg mode DM` —— 我当主持人：讲剧情、扮演 NPC、管人物卡与状态
                 · `.trpg mode 助手` —— 我只掷骰，别的什么都不做
              2. 传剧本（可选）：把剧本文件发到群里，引用它敲 `.trpg scenario`
              3. 起一局：`.trpg new <这一局的名字>`（或者写剧本名，就用那份剧本）
              4. 大家各自：`.trpg join` 报名 → `.pc new <角色名>` 建卡 → `.pc confirm` 确认
                  （属性可以由主持人给、自己 `.st` 填，或者用 `.pc roll` 按规则书掷）
              5. 都确认了：`.trpg start` 开跑

              剧本库里还没有剧本。
              把一份剧本（`.md` / `.txt` / `.docx` / `.pdf` 都行）发到群里，引用它敲 `.trpg scenario` 就收进来了。
              不想要剧本也可以：直接 `.trpg new <随便是什么名字>` —— 那一局没有注入剧本，我自己发挥。
```

三条要记住的：

- **所有命令回执都是"引用回复"**那条命令消息（`sendTextBatch(..., { replyToMessageId })`），所以你一眼能看出它答的是哪句。
- **`1.` 那行报的是当前模式**，缺省是 `dm`，所以没切过的群显示「DM 模式（跑团，我当主持人）」。
- **接管是按会话的**：在 A 群敲只接管 A 群，B 群照常聊天、也敲不到跑团这些命令（`commandDefs()` 对非接管会话直接跳过 override 扩展）。

## 第二幕：传剧本（**可选** —— 格式本来就对时零模型调用）

```
群友B：[文件 灯塔.md]
群友B：.trpg scenario   ← 引用上面那条

[代码] 小鲸鱼：已存剧本「灯塔」：标题「废弃灯塔」，带 3 条旗标、2 张人物卡，正文 1840 字（来源 文本）。
              开局：.trpg new 灯塔
```

- **格式本来就对 → 一次模型调用都不发**。判据是确定性的（`isFormattedScenario`）：开头有没有 frontmatter、整份能不能解析。**这是唯一的分档判据**，不引入第三个档。
- 传的是 PDF 模组、或一段没有 frontmatter 的裸设定时，**走剧情抽取管线**（P7-a）：原文切成几片分别抽结构 → 归并 → 合成一份压缩正文。回执把账目说清楚 —— **调用次数要看得见**（最多 6 片 + 1 次归并）：

```
群友B：[文件 模组.pdf]
群友B：.trpg scenario   ← 引用上面那条

[代码] 小鲸鱼：已存剧本「模组」：标题「模组」，正文 4200 字（来源 PDF，12 页）。
              抽出了 4 个场景、3 个 NPC、9 条线索、2 件道具、6 条机制（原文 18000 字切成 3 片，用了 4 次调用，还有 900 字超出片数上限没进抽取）。待核项 1 条 —— 敲 `.trpg check 模组` 逐条看。
              开局：.trpg new 模组
```

  ⚠️ 「抽出了…」与「待核项…」是**同一行**（`extractedNote` 一次拼出来的）。**"抽了几片"与"还有多少字没抽"分开说**：后者是管理员判断"要不要手工再传一次"的唯一依据 —— 原文切片只到片数上限，超出的那些字一份都没进（原文没丢，在 `raw/` 里）。没有待核项时那一句换成「没有待核项。」；一条机制都没抽到时**不落 `.rule.json`**（落一个空文件会让 `.trpg check` 报"0 条机制"，看起来像抽坏了）。
- **管线没成时退回"只把原文整理成规定格式"那条老路**（一次调用）：

```
群友B：[文件 模组.txt]
群友B：.trpg scenario   ← 引用上面那条

[代码] 小鲸鱼：原文不是剧本格式，已让模型整理过（原文 5120 字）。
              已存剧本「模组」：标题「模组」，正文 3180 字（来源 文本）。
              剧情抽取没成（第 2 片没有返回可解析的 JSON），只做了格式整理 —— 这份剧本没有剧情结构，DM 只能从正文里自己读。
              开局：.trpg new 模组
```

  开头那行「已让模型整理过」**只有后备这一档才有**（抽取那一档已经用"切了几片、用了几次"说得更准了，再补一句等于把抽取降格成排版）。⚠️ 那句里的 `原文 5120 字` 是**原始文本**的字数，而下面 `正文 3180 字` 是**整理之后**的字数 —— 两个数不是一回事，回执里分开写正是为了这个。两条都失败时**两条原因都说出来**：`模组.txt：<管线那句>（退一步只做格式整理也没成：<整理那句>）`，不压成一句 —— 只说一句会把一半事实丢掉。
- 名字不给就用**文件名**（`灯塔.md` → `灯塔`；`模组 v1.2.pdf` → `模组 v1.2`）。没引用文件、也没给名字，回的是剧本清单。
- 引用了一条**没有下载地址**的文件（协议端只给了 `file_id`）时，回执会明说这条路下不来，并给出两条替代路。
- **下载失败与读不出来分开报**：`下载「X」失败：…` vs `读「X」失败：…`。压成一句会让人往错的方向查。

## 第三幕：起一局、报名、建卡、开跑（P2 起是五步）

**3.1 起一局**（**声明**这一局叫什么；写剧本名就用那份剧本，写别的就当标题）：

```
群友A：.trpg new 灯塔
[代码] 小鲸鱼：《废弃灯塔》已经开局，检定规则表是 coc7（COC 7 版检定）。剧本「灯塔」已注入：
              正文 1840 字，预置 3 条旗标、2 张人物卡。接下来让要玩的人敲 `.trpg join` 报名、
              `.pc new <角色名>` 建卡，都确认之后敲 `.trpg start` 开跑。
```

> 这一局的名字、规则表与后面笔记里那个「（COC 7 版）」都来自**剧本 frontmatter**（`title` / `rule` / `system` 三行）。`.trpg new` 里也可以显式覆盖规则表：`.trpg new 灯塔 generic`。判据分三档，别混：**引用的表不存在** → 回落 `generic`，并把那句话写进回执；**表文件本身坏了** → 直接拒绝开局（不静默换一套）；**表选对了但形状不匹配**（拿 `coc7` 去掷 `3d6`）不在开局时报，而是在检定那一刻明确拒绝。

> 名字对不上剧本库时会多一句「（剧本库里没有「X」，这一局没有注入剧本 —— 想用剧本就先传一份）」—— 剧本是可选的。

**3.2 大家报名**：

```
群友B：.trpg join
[代码] 小鲸鱼：已加入《废弃灯塔》（现在 2 人）。
              接下来敲 `.pc new <角色名>` 建一张卡。
```

重复报名会被拒（「你已经在这一局里了」）；满员（**8 人**）会被拒并把上限说出来。

**3.3 建卡**：

```
群友B：.pc new 阿飞
[代码] 小鲸鱼：已建卡：「阿飞」（HP 10/10）。
              属性怎么定听主持人的（有的团自己掷、有的团直接给）。定下来之后敲 `.pc confirm` 确认。
```

**没先报名就直接建卡也算报名** —— 不会把"报名"与"建卡"分成两步让人漏掉前一步。

**3.3b 掷属性（P4，只在规则表支持时）**：

```
群友B：.pc roll
[代码] 小鲸鱼：已掷出一套属性（COC 7 版检定）：
              STR 55、CON 60、DEX 50、APP 45、POW 55、SIZ 75、INT 70、EDU 65
              派生：HP 13、MP 11、SAN 55、DB 0、Build 0、MOV 8
              不满意就再敲一次（确认之前随便重掷）；定下来敲 `.pc confirm`。
```

**规则表没声明 `chargen` 时如实说一句**，并给出 `.st` 这条替代路（**不硬塞一套出来**）：

```
[代码] 小鲸鱼：这一局的规则表（generic）没有属性生成 —— 属性由主持人定，
              你可以用 `.st <技能> <值>` 自己填。
```

**缺属性时明说缺谁**（那意味着规则表把 `CON` 改了名，而不是"算出来是 0"）：

```
（有几项没算出来：规则表里没有 CON、SIZ —— 那几项派生值要这几个名字）
```

**3.4 开跑之前**：

```
群友A：.trpg start
[代码] 小鲸鱼：还差这些才能开始：
              · 10001 还没建卡（`.pc new <角色名>`）
```

**卡没建完/没确认时开不了跑**，而且它**逐人**说清还差谁、下一步敲什么。

```
群友B：.pc confirm
[代码] 小鲸鱼：「阿飞」已确认。
              还差：10001
```

都确认之后：

```
群友A：.trpg start
[代码] 小鲸鱼：《废弃灯塔》开跑！2 位玩家，2 张人物卡。
              接下来直接说话就行 —— 我会接着往下讲。
```

> **这条 4 步的流程可以整个省掉**：让 DM 自己用 `campaign action=start` 开场也行（那条路建出来
> 直接是 `active`）。两个入口共用 `beginCampaign`，差别只有 `status` 一个参数。

**然后群里会安静一会儿，这是对的**：`.trpg start` 是斜杠命令，落成**已读**历史、`wakeEligible: false`，不唤醒模型。DM 不会自己开口，得有人说话。

## 第四幕：游玩一轮（从这里开始烧模型，也在这里模型才说话）

```
群友B：我们进灯塔看看
```

**这一轮 DM 内部做的事（`[内部]`，群里一个字都看不到）：**

```
[内部] campaign { action: "scene", scene: "灯塔一层·门厅" }
[内部] ← 场景已更新：灯塔一层·门厅

[内部] character { action: "create", name: "阿飞", ownerId: "10002", hp: 12, san: 55, stats: { 力量: 60, 侦查: 45 } }
[内部] ← 已建立「阿飞」：HP 12/12、SAN 55/55。

[内部] say { messages: ["门轴锈得厉害，你推了三下才挤开一条缝。……", "……", "接下来可以：…"] }
[内部] ← 已发送 3 条。不要输出"已发送"类汇报，接着推进剧情或直接结束。
```

> 玩家自己的卡**默认就是"玩家已经见过"**（`visible` 不传 = `discovered: true`）。要藏一张卡（还没登场的 NPC）传 `visible: false`，回执会多一句「（玩家还没见过这个人）」。

**群里看到的是：**

```
[模型] 小鲸鱼：门轴锈得厉害，你推了三下才挤开一条缝。里面比外面还冷，空气里有一股海腥味混着煤油。
              借着手电的光，你看见门厅正中有个翻倒的柜台，柜台后面有一道往下的楼梯。
              ——
              接下来可以：
              · 去柜台后面翻一翻
              · 打着手电下楼梯
              · 先退出去，绕到灯塔背面看看窗户
```

**这一轮结束后**：`say` 记了账（`session.sent` 非空）→ 收尾状态 `done` → **不触发兜底建议**。

几条形状上的硬约束（`[模型]`，措辞不保）：

- **普通文本不会到 QQ**。模型不调 `say` 就等于没说话 —— 它的思考过程群友看不到。
- 每轮收尾自己给 **2-4 个可执行选项**（提示词要求的，零成本）。
- **工具改完状态要用 `say` 讲出来**：玩家看不到工具调用，只看到话。反过来，**嘴上宣布了状态变了却没调工具**的话，它下一轮看到的还是旧数值，剧情当场对不上。
- 一次运行 = 游戏里一个回合。**同一个角色一回合只有一次主行动**，重复的同参数调用会被拒。

**还有一条与跑团无关但会影响观感的**：DM 模式**没有** `intercept`，所以普通消息照常走**响应档位**判定。"这一批消息要不要理"是 core 的响应策略，不是跑团能改的。缺省档位（`contextSliderPos: 95` → 4 档「全部响应」）下每句都理；把它调低的群里 DM 会挑着理，**@ 它一定理**。（助手模式不适用：那边整条消息都被拦下了。）

## 第五幕：掷骰与检定

玩家自己掷（**零成本、不经模型**）：

```
群友B：.r 1d100
[代码] 小鲸鱼：1d100 → 43 = 43

群友B：.r 4d6kh3
[代码] 小鲸鱼：4d6kh3 → 6+3+5 = 14（掷出 1,6,3,5，丢掉 1 颗；骰子和 14）

群友B：.r 3d6x
[代码] 小鲸鱼：骰子表达式这里需要一个数字、骰子或括号（支持 3d6、d20、1d100、2d6+3、
              2d6+1d4（多组相加）、4d6kh3/4d6kl3（留高/留低）、(2d6+3)*2（括号与四则）、
              1d100b2/1d100p1（奖励骰/惩罚骰）；骰池(a)、双重十字(c)、命运骰(f) 不支持）
```

- **每一颗骰子都印出来**：`4d6kh3 → 14` 是不可复核的，玩家会问"我掷了哪四颗"。
- `.r` 的解析错误是**直接抛**出去的，`runCommand` 把 `error.message` **原样发进群** —— 那句话本来就是中文 + 可执行的下一步，不换成"掷骰失败"。
- 有战役时掷骰会记进那一局的日志（`.trpg status` 的"最近的掷骰 / 检定"里看得到）。

DM 让模型裁定成败时（`roll` 工具，**模型看得到、群友看不到**）：

```
[内部] roll { expr: "1d100", target: 50, reason: "撬锁" }
[内部] ← 1d100 → 30 = 30 ｜ 对 50 → 成功（差 20）
```

群友看到的是 DM 用 `say` 转述的那句话。

**自己检定（P3）** —— 不用叫 DM，也不花模型调用：

```
群友B：.ra 侦查
[代码] 小鲸鱼：阿飞 的侦查：1d100 → 30 = 30 ｜ 对 45 → 成功（差 15）
```

三种"做不了"分开说：

```
群友B：.ra                       ← 没给技能名
[代码] 小鲸鱼：用法：`.ra <技能>`
              你卡上有：侦查、力量
              （想掷别的表达式就直接 `.r 3d6`）

群友B：.ra 游泳                  ← 卡上没有这一项
[代码] 小鲸鱼：你卡上没有「游泳」这一项。
              有这些：侦查、力量
              （让主持人用 `character` 给你加上，或者想掷别的就直接 `.r 3d6`）
```

**没建卡的人**会被告知先 `.pc new`，**没有战役**时被告知先 `.trpg new`。

**暗骰（P3）** —— `.rh`：

```
群友B：.rh 侦查
[代码] 小鲸鱼：暗骰结果已私聊发送 —— 点开和我的私聊看。
```

群里**只有这一句**（`t-trpg.mjs` 有一条断言钉的是**整串相等** —— 比"不含数字"更强）。私聊里收到的是：

```
[代码] 【暗骰】阿飞 的侦查（45）
       1d100 → 42 = 42 ｜ 对 45 → 失败（差 3）

       你屏住呼吸，指尖在桌沿上停了一瞬 —— 有什么地方不对劲，但你说不上来。
```

前两行是**代码**算的；最后那段叙事来自**一次独立模型调用**（`EXTRA_PROMPT_JOBS.trpg.secretRoll`），
而且那个模型**看不到点数** —— 递给它的只有技能名、技能值与档位，所以它写不出偏袒某一方的叙事。

⚠️ **暗骰不留痕**：这一条**既不进 `campaign.log`、也不进战报**。它唯一的持久痕迹是玩家私聊存档里那条 `我：…`。写进 `campaign.log` 就等于让暗骰在群存档里留下痕迹 —— 而 DM 那一份渲染**会把日志念给模型听**。

> **后果要说清**：DM 也不知道你掷了多少。骰娘语境里的"暗骰"是"只有掷骰的人看得到"，不是"只有 DM 看得到" —— 想要 DM 知道点什么，就用 `.ra` 或者直接说话。

**确认之前改属性（P3）** —— `.st`：

```
群友B：.st 侦查 45
[代码] 小鲸鱼：阿飞 的侦查 = 45。都定好之后敲 `.pc confirm`。

群友B：.st                       ← 不带参数就列出卡上有什么
群友B：.st 侦查                  ← 只给名字就回显当前值
```

**确认之后被拒**（那张卡定下来了，改数值归 DM）：`「阿飞」已经确认过了 —— 开跑之后改数值请让主持人用 character。`

## 第六幕：看笔记（玩家视角，零成本）

```
群友C：.trpg status
[代码] 小鲸鱼：【跑团笔记】《废弃灯塔》（COC 7 版）
              场景：灯塔一层·门厅

              · 阿飞（玩家 10002） ｜ HP 12/12 ｜ SAN 55/55 ｜ 力量 60、侦查 45

              最近的掷骰 / 检定：
              #3 [roll] 10002 掷 1d100 → 43 = 43
```

**这张卡里不会出现**：还没见过的人（`discovered: false`，整张不出现）、`[暗线]` 旗标（`visible: false`，整条不出现）、被标成 `hidden` 的字段（属性那栏变 `???`）。

**会出现的还有**：DM 用 `character` 写过备注时，人物那一行末尾多一段 `｜ 备注：受了刀伤`；`HP` / `SAN` 只在**这个概念真的存在**时才印（`hpMax` / `sanMax` 为 0 就整段不印 —— 通用骰子那条路上很多系统没有 SAN，印一个 `SAN 0/0` 只会让人困惑）。

**只有 DM 看得见的那一份**是另一套渲染：全量 + 逐项标注 `[对玩家隐藏: …]` / `[暗线]` + 一个「玩家已经知道的」小节，另有一道总预算闸门（超了从**最老的日志**开始丢）。

## 第七幕：DM 沉默那一轮（兜底建议）

假如某一轮 DM **一句话都没说**就结束了（`status === 'noreply'`），而且那一轮是**真人**推动的、且过了 3 分钟冷却：

```
[内部] 跑一次小模型，生成 2-4 个行动方向
[内部] 落一条未读的 trpg-note（kind: 'suggest'，标签【行动建议】）→ 唤醒下一轮
```

**下一轮的 DM 自己用 `say` 把它说出来** —— 扩展不代它发群。所以群里看到的仍然只是一段叙事，**看不出"系统给了建议"**。

循环终止由一件事保证：**兜底落下的那条会唤醒下一轮，而那一轮的触发批里只有机器条目、没有真人消息** → 不再兜底。

## 第八幕：揭示暗线（回流）

```
[内部] campaign { action: "reveal", name: "守塔人其实是凶手" }
[内部] ← 暗线「守塔人其实是凶手」现在对玩家可见了。接下来在叙事里自然地承接它 —— 别直接念出来。
[内部] 同时落一条未读的 trpg-note（标签【跑团笔记】）→ 唤醒下一轮
```

下一轮 DM 开口时，**群里看到的只是叙事**（比如「……你忽然想起，昨晚他手上的伤，位置和灯塔铁门上那道血迹一样高。」）。从这一刻起，群友敲 `.trpg status` 的那份笔记里会多出这条旗标。

**标签是模型唯一的判据**：【跑团笔记】该自然承接、【行动建议】该组织语言说出来 —— 两张标签的正文形状不同，压成一个它就分不出来。

## 第九幕：助手模式的对照

```
群友A：.trpg mode 助手
[代码] 小鲸鱼：已切到助手模式（只掷骰），下一轮运行生效。
```

（如果这个群已经开着局，末尾还会多一句 `这一局的存档留着，切回 DM 就接着跑。`）

```
群友B：3d6
[代码] 小鲸鱼：3d6 → 4+2+5 = 11          ← 代码掷的，一次模型调用都没发生

群友B：你们在聊啥
[代码] 小鲸鱼：（一个字都不回）            ← 拦下，不惊动模型、也不刷屏

群友B：3d6 帮我看看
[代码] 小鲸鱼：（一个字都不回）            ← 半句话；判据是"整串就是一个合法表达式"

群友B：.r 3d6x
[代码] 小鲸鱼：骰子表达式这里需要一个数字、骰子或括号（…）   ← 斜杠命令不受模式影响

群友A：.trpg status
[代码] 小鲸鱼：当前是助手模式（只掷骰）：发一个骰子表达式（3d6、d20、2d6+3、4d6kh3…）我就掷。
              要变成跑团（我当主持人）：`.trpg mode DM`。
```

- **那个群里一次模型调用都不会发生**：认得出骰子就掷、认不出就静默拦下。
- **连人格都不注入**（`prompt()` 返回空 body）。能唤醒模型的只剩两条与扩展无关的路径（全局主动冒泡、异步结果回流），而那两种情况下"什么都不说"正是要的行为。
- **工具表只剩 `say` + `roll`** —— 不是"靠提示词请它别动别的"：`campaign` 与 `character` **压根不在它手里**（DM 模式是四个工具，助手模式是两个）。
- **斜杠命令不受模式影响**：那些是**人**的动作，而且切回 DM 时那一局最好还在原地。

## 第十幕：收团

**跑完一局**：

```
群友A：.trpg end
[代码] 小鲸鱼：《废弃灯塔》收团。这一局跑了 2 小时 13 分，留下 47 条记录、2 张人物卡。
              玩家：阿飞（10002）、小满（10003）
              走过的场景：码头 → 灯塔一层·门厅 → 控制室
              没解开的事（原本的暗线）：真凶是守塔人
              （这一局的存档已经清掉；战报留着。要再开一局就敲 `.trpg new <名字>`）
```

> 摘要四项都是**代码从状态里算出来的**（时长/玩家/走过的场景/没解开的暗线）—— 敲它的是人，
> 而人要看的是「记下来的事实」。**"没解开的事"取的是暗线旗标**（`visible: false`）。
>
> `.trpg end` **删掉这一局的存档**（不是封存）：不删的话下一局只能靠 `restart` 清，而那条路
> 会连带清掉人物卡。代价是这一局的 `campaign.log` 也随之没了 —— 完整历史在**战报**里
> （`data/trpg/journal/<会话>.jsonl`，append-only，收团不动它）。

**这个群不跑团了**（与收团是两件事）：

```
群友A：/能力 卸载 trpg
[代码] 小鲸鱼：✅ 已解除「跑团（TRPG）」对这个会话的接管

群友B：今晚吃啥
[模型] 小鲸鱼：……（变回普通群友，主人格与内置工具全部回来）
```

> **内置工具到底几个**：静态表 `buildToolDefs()` 是 **27** 个，而 `agent-runner` 每次运行会按能力开关再滤一遍（视觉、联网、转写、出图、热搜）—— 默认配置下关着转写/出图/热搜，所以模型实际拿到 **24** 个。所以这里只写"全部回来"，不写数字：那个数随配置变。

一局的存档留在 `data/trpg/<群号>.json`（人物卡、场景、旗标、剧本快照、最近 60 条日志），下次 `/能力 加载 trpg` 接着跑。

**另一条退出路径**：`extras.idleUnloadMs`（`0` = 不限）到点后，**接管会自动交还主流程** —— 最后一条绑定的实现被 `dispose()`，会话回到主人格。扩展被在设置页关掉（不重启）时也会干净退回，不会留下"接管人格 + 零工具"的静默坏状态。

## 第十一幕：打一场架（P5，三条命令全部零模型调用）

**排一次先攻**：

```
群友A：.combat start
[代码] 小鲸鱼：先攻（按 DEX）：
              1. 阿飞
              2. 阿豪
              3. 教授
              第 1 轮，轮到「阿飞」。
```

> ⚠️ **回执里不印先攻数值**，只有名字与序号 —— 那个数就是卡上的属性（规则表里的 `initiative`，
> 缺省 `DEX`），而 `character` 的 `hidden: ['stats']` 存在的理由正是"藏属性"。**模型那一侧照常
> 带数值**（`[内部]` 里那串是 `1. 阿飞 65`），因为它本来就看得到全量状态 —— 分岔是有意的：
> 群里看到"谁先动"，DM 心里有数"为什么"。

**重排**（`.combat start` 再来一次 = 重排，中途加人就用它）：

```
群友A：.combat start
[代码] 小鲸鱼：已重新排好（按 DEX）：
              1. 阿豪
              2. 阿飞
              3. 教授
              第 1 轮，轮到「阿豪」。
              （这次是重排 —— 上一场的顺序作废，从第 1 轮重新开始）
```

**卡上没有那个属性**（**照排**，按 0 排后面，并把这件事说出来）：

```
[代码] 小鲸鱼：先攻（按 DEX）：
              1. 阿飞
              2. 阿豪
              3. 教授
              第 1 轮，轮到「阿飞」。
              （教授 的卡上没有 DEX，按 0 排在后面）
```

**推一格**：

```
群友A：.combat next
[代码] 小鲸鱼：轮到「阿豪」。
              顺序：阿飞 → 阿豪 → 教授
```

> 倒下的人自动标出来、且**推的时候自动跳过** —— `顺序：阿飞 → 阿豪（倒下） → 教授`。
> 判据是"顺序里那个人**现在**什么样"（HP 掉到 0 了 / 卡被删了）而不是"顺序里记着什么"，
> 所以 DM 刚把一个人打趴，下一次推进就会跳过它，**不需要任何一处额外记账**。
> ⚠️ **`hpMax` 为 0 的卡不算倒下**（那是"这套规则没有 HP 概念"的写法，见 `.pc new` 那一栏）——
> 不然那套规则下整张顺序表会当场全灭。

**收场**：

```
群友A：.combat end
[代码] 小鲸鱼：战斗结束。
```

**三条"做不了"分开说**：

```
[代码] 这个会话还没有开局 —— 先让谁来敲 `.trpg new <名字>` 起一局。
[代码] 现在没有在进行中的战斗 —— 先敲 `.combat start` 排一次先攻。      （`.combat next`）
[代码] 现在没有在进行中的战斗。                                      （`.combat end`）
[代码] 没有可以参战的人 —— 先攻序排的是「玩家已经见过、还站着」的人物卡。先敲 `.pc new <角色名>` 把在场的人建出来。
[代码] 规则表读不出来，排不了先攻：<原因>                              （不换一套顶上去）
```

**裸 `.combat`**（认不出的子命令落到它上面，**不静默**）：

```
群友A：.combat 乱写
[代码] 小鲸鱼：用法：
              · `.combat start` —— 按先攻属性排一次顺序并公布（再排一次 = 重排，中途加人就用它）
              · `.combat next` —— 轮到下一个人
              · `.combat end` —— 这一场打完了
```

**模型那一侧**（`campaign` 的 `action=combat`，`sub` 选 `start` / `next` / `end`）：

```
[内部] campaign { action:"combat", sub:"start" }
       → 先攻（按 DEX）：
         1. 阿飞 65
         2. 阿豪 55
         3. 教授 40
         第 1 轮，轮到「阿飞」。
[内部] campaign { action:"combat", sub:"next" }
       → 轮到下一个了。
         第 1 轮，轮到「阿豪」。
         顺序：阿飞 → 阿豪 → 教授
```

> **两条路共用 `model/combat.ts`**（`.combat *` 与 `campaign action=combat`），差别只有措辞与
> "数值给不给"。`combat` 这条**不占行动配额**（`quota: false`）：指针不是任何角色的行动，
> 它是 DM 的记账 —— 占配额的话 DM 会刚好在"轮到某个人、该给他记伤害"那一刻被自己的记账锁在门外。
>
> ⚠️ **代码不拦越权行动**（决策 9，知情取舍）：它只管"轮到谁"，不管"这一轮该不该是他"。
> 顺序错了不会有任何机制发现，只能靠 DM 照提示词走 —— 所以两边回执**每次都把当前行动者念出来**，
> 让 DM 手里有一个可以对的锚。
>
> **"行动即推进"**：`character` / `campaign` 的**写动作**收尾时，按"谁动了"自动把指针推一格 ——
> 判据是**按名字匹配**（`actors` 里有当前行动者）而不是"这一轮有人做过事"：后者会在极常见的
> "玩家掷一次骰、DM 接着给敌人记伤害"里**连推两格**，而那两件事属于同一个人的同一个回合。

**玩家视角的状态卡里也会带一段战斗**（`.trpg status` / `.pc show`，零成本）：

```
[代码] —— 战斗（第 2 轮）——
       轮到「阿豪」。
       1. 阿飞（倒下）
       2. 阿豪
       3. 教授
```

> 这一段**只在有战斗时出现**（不是常驻一句"当前没有战斗"）。它同样**只印名字**：
> 群友看得见"谁先动"，看不见"凭什么"。**没见过的整张卡不给看** —— 顺序里那些
> 玩家尚未 `discovered` 的人会**从这一段里被滤掉**，所以有时群里的顺序会比 DM 手里短。
> 你自己那张卡**无条件可见**（`.pc show` 里就算你还没被自己"见过"也在）。

群友A：.log export
[代码] 小鲸鱼：战报已导出：跑团战报-20261017-2143.md（47 条）。
```

那份文件随群文件发出去，内容长这样：

```
# 跑团战报 · group:123456

- 导出时间：2026-10-17 21:43:07
- 条目：47 条

---

1 21:12:04 [场景] 场景：码头

3 21:16:08 [掷骰] 阿飞 掷骰：1d100 = 42
4 21:18:22 [检定] 阿飞 的侦查：1d100 → 30 = 30 ｜ 对 45 → 成功（差 15）
5 21:20:47 [状态] 先攻（按 DEX）：阿飞 → 阿豪 → 教授
…
```

> **战报是 append-only 的旁路**（`data/trpg/journal/<会话>.jsonl`，一行一条 `{seq, ts, kind, text}`）。
> 为什么不把 `campaign.log` 存久一点：那个数组**每一轮都进 system prompt**，60 条的上限是成本
> 不是洁癖；而"这一局打过什么"要给**人**看，要求的是完整。两个需求挤在一个数组上只能二选一。
>
> ⚠️ **暗线与隐藏字段进不了战报** —— 这是 P6 落地时发现的一条真泄漏：`mirrorLog` 原本把
> `campaign.log` **原样**镜像进战报，而 `state` / `scene` 两类日志的正文里混着
> `隐藏：pools/notes`、`旗标：真凶是医生 = 是（暗线）`。导出之后那份文件**发进群**，
> 等于把刚藏好的东西又说了一遍。现在判据是**按条**的（`TrpgLogEntry.visible`），而且由
> **写入那一侧**决定 —— 暗骰的结果与私密叙事压根不进 `campaign.log`（决策 7），所以它们
> 也就不进战报；**导出时再按同一条判据查一遍**（发布边界上的第二道，判据只有一份）。
>
> ⚠️ **先攻那一行只记名字顺序**（`先攻（按 DEX）：阿飞 → 阿豪 → 教授`），不记数值 ——
> 同一理由（那是卡上的属性，而 `hidden: ['stats']` 存在的意义就是藏属性）。

**三条"导不了"分开说**：

```
[代码] 这个会话还没有战报 —— 战报从这一局开跑之后开始记（掷骰、检定、剧情记录都会进去）。
[代码] 这台机器没接上传文件的通道，发不了 —— 战报存在本机，管理员能在设置页的「跑团」里看到它（共 47 条）。
[代码] 战报导出失败：<原因>（战报还在本机，没有丢）。
```

> ⚠️ `createLogCommand` 里还有一条 `这个部署没有接战报 —— 导出不了。`，但它**在生产里到不了** ——
> `impl.ts` 每次都 `new JournalStore()` 递下去，`journal` 从来不是 `null`。它只是"宿主没接战报"
> 那个假想形状的兜底。别把它当成一条真的会发生的话。

**裸 `.log`**（认不出的子命令落到它上面）：

```
群友A：.log
[代码] 小鲸鱼：用法：
              · `.log export` —— 把这一局的战报导出成一份文件发进群（含每一轮掷骰、检定与剧情记录）
```

> **面板上还有第三列**：设置页「跑团」那一栏列出磁盘上的**剧本 / 规则表 / 战报**三类，
> 每一行一个删除按钮。战报那一类的 confirm 文案与另两类**说的是相反的话** ——
> 剧本与规则表删掉还能再传，战报删掉就没了。
>
> 面板那份 store 与扩展读写的是**同一批文件**（目录的薄视图），所以导出完刷新设置页就能看到它。

## 第十三幕：核对抽取结果（`.trpg check`，P7，零模型调用、零写入）

抽取管线（第二幕）把一份非结构化的模组变成三样东西：`.md`（压缩正文，**唯一进 system prompt 的那一份**）、`.struct.json`（剧情结构）、`.raw/`（原文切片，保底）。**抽得对不对、有没有条目被上限裁掉、引文对不对得上原文 —— 群友在群里一处都看不到。** 这条命令就是那个出口：只读目录与三个伴生文件，**一个字都不写**，所以随时可敲、敲多少次都不要钱（手改结构文件再敲一次就能核对，`read()` 的缓存签名把三个伴生的 mtime 都算进去了）。

```
群友A：.trpg check 模组

> 上面这一段是**真跑出来的**（临时数据目录 + 一份手造的 `.struct.json` / `.rule.json`），不是照着源码编的。`describeMechanic` 的拼法是 `${note || 触发条件}（${type} / ${触发条件}）`，所以**模型没给 `note` 的那条会印成 `无条件（narrative_hook / 无条件）`** —— 看着像重复，但它如实反映了"这条机制没写说明、也没有触发条件"，而那正是模型判断该不该照它来的依据。想让它好看就得在这里编一句话，那才是真的假话。

- **规则扩展那一栏三类分开列**，判据只有一条：`effect.handler` 是不是 `narrate`（编译期就定了，不是这里猜的）。非分不可的理由是：**可执行的那几条真的会改检定与伤害**，而叙事那几条不会 —— 混在一张单子里，管理员没法回答"这份模组到底改了什么判定"这个唯一要紧的问题。**可执行的与只作叙事的都一条不截断**（少印一条 = 管理员以为这份模组没这条规则）。
- **`待核项` 是这条命令存在的第二个理由**。它们来自五个地方，措辞都是编译期写好的句子（这里不重写一份 —— 重写必然与那边漂移）：原文太长只抽了前 N 片 / 某一片没抽出来 / 某类条目合并后超过上限 / 引文在原文里找不到 / 机制编译时降级。超过 8 条时只印前 8 条并说"它们都在 struct.json 里"。
- **`正文 N 字，原文切片 N 片`**：前者是**每轮进 system prompt 的成本**，后者是原文保底切片有几片。这里**不报"丢了多少字"** —— `droppedChars` 没落盘，但管线把它写进了 `warnings`，所以那句话会出现在下面的待核项里。
- 判据分档与抽取那一侧一致，**不引入新档**：
  - 有结构 → 印统计；有伴生文件但读不动 → `剧情结构：没有可用的 —— 原因见下面的「伴生文件」`（措辞刻意不是"还没有抽取产物"：抽过，只是文件坏了）；
  - 手写的、格式本来就对的剧本（压根没走抽取）→ `剧情结构：这份剧本还没有抽取产物（伴生结构）`，末尾那句"下一步"也换掉：`这份剧本没有抽取产物。手写的、格式本来就对的剧本不会走抽取，那是正常的；要抽一遍：把原始文件重新发到群里、引用它敲 \`.trpg scenario 模组\`。`；
  - 规则扩展三档分开说：`没有 —— 这份剧本的检定按基础规则表走。`（`ruleExt` 字段压根不在）/ `空的（文件在，但里面一条机制都没有）。` / `读不出来（这份规则扩展坏了，用它的那一局开局会被拒）：` 后面逐条列 `compiled.problems`。
- **最后那段"下一步"看的是"这份剧本此刻在不在用"**：正在用（`campaign.scenario.id` 对得上）时印 `《模组》正在用这份剧本 —— 改完结构文件再敲一次这条命令就能核对。`，那时"去开一局"是**错的提示**。
- 名字对不上时走的是 `read()` 那一句：`没有叫「乱写」的剧本。现在有：模组`（**清单由 `read()` 自己带上**，这里不再拼第二遍 —— 拼一遍会让同一句话出现两次）。

**不带名字**（或只敲 `.trpg check`）：

```
群友A：.trpg check
[代码] 小鲸鱼：用法：.trpg check <剧本名>
              · 把这份剧本抽出来的东西摊开看：抽到几个场景 / NPC / 线索，有哪些待核项，原文切了几片
              · 一次模型调用都不发，也不改任何文件 —— 随时可以敲
              · 手改了 data/trpg/scenarios/<名字>.struct.json 之后再敲一次，看到的就是新的那一版

              剧本库里现在有：模组
              （要再加一份：把文件发到群里、引用它敲 `.trpg scenario`）
```

> **为什么是第三份渲染**：展示层已经有两份投影（`renderForModel` 全量 + 标注 / `renderForPlayers` 藏起来的不出现），这一份的受众是**管理员** —— 它要报**抽取的账**（切了几片、有几条待核项、哪个伴生文件读不动），还要说**下一步敲什么**。模型与玩家都不需要这两样。所以它**不复用** `describeStruct`（那一份是给模型的压缩视图：每类封顶 8 条、待核项只给一个计数）—— 共用会让两边漂移，而漂移的表现恰恰是"管理员看到的与模型看到的不是同一件事"，那正是这份回执要回答的问题本身。
>
> **已知代价**（与 `.trpg scenario` 同源）：白名单群里**任何群友**都能敲它。这不增加泄漏面 —— 同一个群里任何人本来就能传一份剧本把它覆盖掉。要收紧只需在 `commands/verify.ts` 那个 handler 里加一句判据。

## 已知文案瑕疵

**1. ~~`.trpg start` 的回执最后一句是写给模型的~~（P2 已修）**

`beginCampaign` 被 `.trpg new`（人敲）与 `campaign action=start`（模型调）**共用**，而它的回执整段是模型语域，于是群友敲一次就会在群里看到「接下来用 character 的 action=create 补上玩家角色」。

**P2 顺手修掉了**：`beginCampaign` 现在按 `status` 分岔 —— `preparing`（人走的那条）给的是「让要玩的人敲 `.trpg join` 报名…」，`active`（工具走的那条）才保留模型语域那句。

**共用判据仍然是对的**（"已经开过局怎么拒、剧本读不到怎么办、规则表坏了怎么办"不该有第二份答案）—— 变的只是**回执的尾巴**，而它本来就该跟着"这一局给谁看"走。**模型那边不受影响**：它下一轮从 system prompt 的【当前跑团状态】读到新局面。

**2. `已切到DM 模式（跑团，我当主持人）` 中间缺一个空格**（纯观感，**仍在**）

`已切到${MODE_LABEL[next]}` 直接拼接，而 `MODE_LABEL.dm` 以 `DM` 开头。切到助手模式那半边（`已切到助手模式（只掷骰）`）看不出问题 —— 中文开头天然有分隔感。见 [mode.ts:31](src/extra/trpg/commands/mode.ts#L31)。

**3. ~~群友可见的回执里带着字面的 `**`~~（A5 已修）**

写这份文档时逐条跑命令发现的：**七处**回执把 Markdown 的加粗记号原样发进了群（QQ 不认 Markdown，所以那些星号**原样显示**）。位置是 `commands/mode.ts` / `commands/combat.ts` / `commands/character.ts` / `render/players.ts` / `render/status.ts`（三处）。

**修法是统一去掉加粗**（不是"按受众分两份"）：当初担心的那一处 —— `renderScenarioList` 同时进 system prompt —— **是个误判**。它只被三处调用（`.trpg scenario`、`.trpg new` 不带名字那一次、向导），**三处都是群友可见**；真正进 system prompt 的是 `renderBriefing`，那是另一个函数、另一段拼装，它**不调用** `renderScenarioList`（见 [status.ts:37](src/extra/trpg/render/status.ts#L37)）。所以"受众不同就必须是两份实现"在这里**不适用** —— 那一份文本自始至终只有一个受众。判据留在了那个文件头的注释里（[status.ts:7-9](src/extra/trpg/render/status.ts#L7-L9)）。

**守护是 `t-trpg.mjs` 的 5q 段（两层，缺一不可）**：① **行为层** —— 把**每一条**命令真敲一遍（"还没有局"与"真开一局"两遍，成功与失败两条路都走到），逐个回执找 `**`；② **源码层** —— 剥注释后扫**群友可见文案的全部落点**（跑团的 `commands/` 与 `render/`，**外加主流程的 `web/onebot/commands.ts`** —— `/能力` 的回执也是发进群的话），并配一条**正对照**（同一个扫描在 `rules/dice.ts` 上必须找得到 `**` —— 那是乘方运算符），否则扫描本身失灵时上一条是空转的。行为层不能省：文案可能是**拼接**出来的（`formatCheck` 那种），只扫字面量会漏。

⚠️ **② 那个"外加主流程"是补出来的，不是一开始就有**：A5 修完时源码层只扫 `extra/trpg/`，于是 `/能力` 回执里那句 `只接管**本群**`（[commands.ts:376](src/web/onebot/commands.ts#L376)）**原样发进了群，而没有任何断言看得见**。现已改成 `只接管「本群」`，扫描也扩到了那个文件 —— 探针实测：把 `**` 加回去，5q 红 1 条并报出 `web/onebot/commands.ts:376`。（报出来的行号取自**原文**而不是剥完注释的文本：`stripComments()` 的块注释分支会把注释里的换行一起丢掉，而那个文件通篇是 JSDoc —— 实测同一行按剥完的文本数出来是 269。）

## 怎么复核

**`[代码]` 的那些字面量**可以直接跑一遍打印出来（用临时数据目录，**不碰真实 `data/`**）：

```bash
npm run build
QQ_AGENT_DATA_DIR=$(mktemp -d) node --input-type=module -e "
const { createRuntime } = await import('./dist/extra/trpg/impl.js');
// 两条投递口子都接上，否则 `.log export` 与 `.rh` 走的是**另一条分支**（'没装通道'那句）。
let sent = null;
const priv = [];
const cmds = createRuntime({
  sendFile: async (n, f, c) => { sent = { n, c }; },
  sendPrivate: async (to, text) => { priv.push({ to, text }); }
}).commandHandlers;
// 键是 `<命令> <子命令>`（带空格），所以取前两个词 —— 认不出就退回第一个。
const at = (t, key = 'group:shop', senderId = '10001') => {
  const w = t.trim().split(/\s+/);
  return (cmds[`${w[0]} ${w[1] ?? ''}`] ?? cmds[w[0]])(
    { chatKey: key, senderId, text: t, media: [], replyToMessageId: null });
};
for (const t of ['.trpg status', '.trpg mode', '.trpg mode 助手', '.trpg status', '.trpg mode DM',
  '.trpg scenario', '.trpg new 灯塔', '.trpg start', '.pc new 阿飞', '.pc show', '.trpg 乱写', '.r',
  // `.st` 要排在 `.ra` / `.rh` **之前**：先填上「侦查」那一项，后两条才走得到
  // 「真的掷一次」那条路（否则它们回的是「你卡上没有这一项」—— 那也是文案，但不是 formatCheck 那一串）。
  '.st 侦查 45', '.ra 侦查', '.rh 侦查', '.ra', '.ra 游泳',
  '.combat start', '.combat next', '.combat 乱写', '.combat end', '.combat end',
  '.log', '.log export',
  // 剧本库是空的（这一段没引用任何文件），所以这两条走的是「没有叫…的剧本」与「用法 + 清单」
  // 两条路 —— 它们同样是群友可见文案，照样要逐字核。**真抽取过的回执要另跑一次真上传**。
  '.trpg check', '.trpg check 灯塔']) {
  console.log('>>> ' + t + '\n' + String(await at(t)) + '\n');
}
console.log('=== 导出的文件 ===\n' + (sent ? sent.n + '\n----\n' + sent.c : '(没有发出)'));
console.log('=== 私聊发出去的内容 ===\n' + (priv.length ? JSON.stringify(priv, null, 2) : '(没有发出)'));
"
```

> ⚠️ 这段是**按顺序**跑的，所以 `.combat start` 会排在 `.pc new` 之后 —— 那时只有一张卡、
> 而且它还没 `confirm`。要看到"真的排出先攻"那一串，得先 `.pc confirm` 再 `.trpg start`。
> 上面那段只是把**每条命令各自的回执**打出来核对字面量，不是一条完整流程。
>
> **第二幕那两条回执**（抽取路 / 后备路）与**第十三幕**那一整段不能这么跑：前者要真的发模型调用，后者要有抽取产物。复核它们的办法是**注入依赖 + 手造伴生文件**（两边都不碰真网络、不碰真数据）：
>
> - 抽取路 / 后备路 / 两条都失败：直接调 `saveScenario(input, name, store, deps)`，把 `extract` 注入成一份固定 `DocumentText`、`analyze` 注入成"成功"或"失败"、`format` 注入成"成功"或"失败"。下载那一步用**回环 HTTP 服务**喂几字节即可（记得先 `updateConfig({ security: { allowPrivateImageHosts: true } })`，跑完复原）。
> - 第十三幕：用 `ScenarioStore` 的 `saveScenarioText` + `writeExtras` 往临时数据目录里落一份 `<id>.md` + `<id>.struct.json` + `<id>.rule.json` + `raw/`，再走上面那段命令脚本敲 `.trpg check <id>`。
>
> 上面那两段 `[代码]` 就是这么跑出来的 —— **不是照着源码编的**。这一点值得强调：编出来的示例会在最要紧的地方失真（比如 `describeMechanic` 在模型没给 `note` 时会印出 `无条件（narrative_hook / 无条件）` 这种看着像 bug 的重复），而那种失真正是这份文档唯一能提供的价值。
>
> `.ra` 那一串（`1d100 → … ｜ 对 45 → …`）走的是 `formatCheck`，所以**掷出多少要看运气** ——
> 核对的是**形状**（档位名只印一次、`差 N` / `超出 N` / `正好` 三选一），不是具体的数。
> `.rh` 的点数**不在这份输出里**（它在上面那串私聊内容里）—— 群里那一句逐字只有
> `暗骰结果已私聊发送 —— 点开和我的私聊看。`

掷骰的格式化（`formatRoll` / `.r` 的报错）同理，`load('extra/trpg/rules/dice.js')` 之后拿固定 `rng` 调一次即可。

**`[模型]` 的那些只能靠真机冒烟**：真 OneBot + 真模型下"DM 会不会真的调工具改状态""它会不会照提示词每轮自己给选项""它看到【跑团笔记】/【行动建议】两个标签会不会做出不同反应" —— 套件能证明的是接线对（工具表、提示词、账本、收尾状态、标签分得开），**证明不了模型用得对**。
